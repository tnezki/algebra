SYSTEM LESSONS FOR REVIEW
-------------------------
1. Representation metadata is not evidence that the representation actually exists. Future Bank builds should audit the final student-facing bytes/action: a Graph item must contain a usable graph, and a Table item must contain a real table or explicitly require the student to build one.
2. Completion-model generators should expose only the givens. A fully completed diamond can leak the answer and can hide incorrect generated values.
3. Figure uniqueness must be checked by mathematical meaning, not only filename or hash. Independently named graphs can still reuse the same roots, equation, data, or answer-bearing instance.
4. When a task asks students to critique a visual error, instantiate the flawed visual itself when the representation is the evidence being analyzed; prose describing the graph is weaker evidence.
5. Neutral blank workspaces are legitimate shared assets. Keep them as explicit reuse exceptions so uniqueness gates focus on content-bearing representations.
