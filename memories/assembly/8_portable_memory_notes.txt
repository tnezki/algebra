INTRO READING RULES

Write AT LEAST 5 paragraphs (8th grade reading level).
Max 3 sentences per paragraph.

The Stop and Discuss block that follows has 3 questions.
These questions are designed BEFORE the reading is written.
The reading is then written to answer them:

  Paragraph A: Contains the answer to Stop and Discuss Q1.
               The FIRST sentence sets context — it does NOT answer Q1.
               The answer appears in the 2nd or 3rd sentence, embedded
               in a fuller explanation. Never lead with the answer.

  Paragraph B: Contains the answer to Stop and Discuss Q2.
               Same rule: first sentence is background or transition.
               Q2's answer is embedded in the 2nd or 3rd sentence.
               Do not mirror the structure of Paragraph A too closely.

  Paragraph C: IMPLIES the answer to Q3 without stating it.
               Q3 is conceptual; students must infer from the paragraph.
               The paragraph introduces a situation, example, or
               consequence — not a definition that gives the answer away.

  Paragraph D: Additional information not tied to any S&D question.
               Use Key Representations from the assessment plan.

  Paragraph E+: Additional information not tied to any S&D question.
                Use Modeling Opportunities or contextual extensions.

Planning steps:
  1. Write Q1, Q2, Q3 first (based on I-cans and Key Representations).
  2. Write paragraphs A, B, C to answer them (A direct, B direct, C inferential).
  3. Write paragraphs D, E+ for additional content.
  4. Check: can Q1 be answered directly from A? Q2 from B?
     Can Q3 be answered by careful reading of C (not stated outright)?
  5. If not: revise before writing the HTML.

MATH NOTES BODY RULES

Include Math Notes ONLY when the next Example introduces a concept
students have not seen. Do NOT force one before every Example.
Skip if the next Example is an application of an already-introduced concept.

Math Notes must work across grades 6-12 and across math courses. Do not
write notes that only name this unit's topic. Write notes around the
mathematical action students are learning: evaluate, compare, rewrite,
graph, interpret, solve, classify, estimate, justify, or critique.

GRAPHS ARE THE DEFAULT, NOT THE EXCEPTION.
For any Math Notes that involves:
  • Reading or evaluating from a representation (equation, table, graph)
    → TYPE D: include an actual graph; mark the key point or value on it.
  • Evaluating function notation (f(3), g(-2), etc.)
    → TYPE D: show the evaluation from ALL FOUR when possible:
      equation (substitute), table (find the input), graph (mark the
      point at x=input), and context (state what the input and output mean).
  • Comparing or critiquing two representations (equation vs table, table
    vs graph, graph vs context, etc.)
    → TYPE D: include an actual graph, table, or visual model that makes
      the agreement or mismatch visible.
  • Function families (linear, quadratic, exponential, absolute value)
    → TYPE D: include an actual graph showing the family's shape and key
      features. Do not rely only on family names.
  • One-output rule, mapping diagrams, or relation/function decisions
    → Use make_scatter_plot to show allowed vs not-allowed cases when
      possible. If scatter is not appropriate, use another graph_tool.py
      visual that makes the repeated-input evidence visible.
  • Expressions, equations, inequalities, or structure
    → Use a graph, number line, area model, balance model, table, or other
      graph_tool.py visual when it makes the structure easier to see.
  • Purely definitional notes with no visual component (e.g. listing
    properties of a notation system)
    → TYPE A or B is acceptable only if a visual would not improve the note.
    If in doubt, still include a graph or visual model.

For every Math Notes block, ask: "Would a student understand this
better if they saw a graph or visual model?" If yes — build the visual
with graph_tool.py. Do not merely say a graph would help.

ACTUAL ARTIFACT REQUIREMENT:
  Do not merely mention equation, table, graph, or context in bullets.
  If a Math Notes rule says to use a representation, that representation
  must physically appear in the Math Notes body as actual HTML, MathJax,
  table.values, or a generated figure.

  Required artifacts by representation:
    • Equation or symbolic rule: include an actual MathJax equation,
      substitution line, expression rewrite, inequality, or equation step.
    • Table or organized values: include an actual <table class="values">
      unless the table is truly unnecessary for that note.
    • Graph or visual model: include an actual <figure class="notes-figure ...">
      whose image is generated by graph_tool.py.
    • Context or verbal meaning: include a concrete sentence naming what
      the input, output, solution, point, intercept, factor, coefficient,
      or feature means in the situation.

EVALUATING FUNCTION NOTATION REQUIREMENT:
  When the Math Notes introduces or reviews evaluating function notation,
  TYPE D must include all four of these artifacts when possible:

    1. Equation: an actual substitution line, such as
       $$f(3)=2(3)+1=7$$
    2. Table: an actual values table containing the input and output.
    3. Graph: an actual graph with the evaluated point marked.
    4. Context: a sentence such as "If x is 3 hours, f(3)=7 means the
       output is 7 miles after 3 hours."

  The note must make clear that all four representations answer the same
  question: "When the input is 3, what is the output?"

MATCHING PROBLEMS — mandatory scramble rule:
  When an Example or YTI asks students to match items (graphs to
  equations, tables to equations, contexts to representations, etc.),
  the correct answers must NOT fall in position order.
  If graph 1 → equation 1, graph 2 → equation 2, graph 3 → equation 3,
  students can answer by position without any mathematical reasoning.
  ✗  Graph A matches y=x+4 (listed first), Graph B matches y=x−3 (listed
     second) — students write 1-2-3-4 without reading any math.
  ✓  Shuffle at least one side so that answer n ≠ position n.
     Example: list equations as y=x−3, y=2x+1, y=x+4, y=−x+2
     while graphs stay in a fixed order — now matching requires analysis.
  This rule applies to all match tasks regardless of number of items.

YTI RULES

YTI problems are AI-derived, parallel to the paired Example.

MATHJAX RULES

  window.MathJax config MUST come before the CDN script.
  processEscapes: true — always include.
  CDN: cdn.jsdelivr.net only.
  Delimiters: $...$ inline, $$...$$ display. Never \(...\) or \[...\].
  Currency in prose (outside math): write as \\$5 or just "5 dollars"
    — do NOT wrap in $...$. Currency inside math context: use \\$ inside $...$.
  Math comparisons: \lt and \gt not < and >.
  Do NOT use $ to wrap numbers that are not being typeset as math.
    ✗  "multiply the input by \$4$ and subtract \$1$"
    ✓  "multiply the input by 4 and subtract 1"
    ✓  "multiply the input by $4$ and subtract $1$"  (math typeset, no \\$)
