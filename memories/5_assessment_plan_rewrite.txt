CRITICAL UNIT-SAFETY RULE - DO THIS BEFORE EDITING
============================================================

Before changing the assessment plan, determine two things:

1. TARGET UNIT
   Infer the target unit from the sixteen formative assessment
   filenames, <title> tags, and assessment-title headers.
   Example: files named unit2_dok1-1.html and headers such as
   "Unit 2 DOK 1.1 Slope from Points" mean the target unit is
   Unit 2.

2. TEMPLATE UNIT
   Infer the unit currently shown in the assessment plan HTML
   from the <title>, main <h1>, inferred-input comments, formative
   href values, summative href values, and visible unit labels.

The target unit from the formative files overrides the template
unit from the assessment plan file.

If TARGET UNIT and TEMPLATE UNIT match:
  - This is a same-unit formative-section rewrite.
  - Preserve locked elements according to the normal locked-element
    rules below.
  - Preserve href values character-for-character.

If TARGET UNIT and TEMPLATE UNIT do NOT match:
  - The assessment plan file is a previous-unit template, not a
    locked current-unit plan.
  - You MUST convert the plan shell to the target unit.
  - Do NOT leave the old unit number, old unit title, old formative
    paths, old summative paths, or old href roots in the output.
  - In this mismatch case, unit identity and path conversion override
    the normal "do not touch" and "href preservation" rules.

A delivered file that still says "Unit 1" when the formative files
are Unit 2 is a failed output, even if the formative descriptions
were updated correctly.

PART 1 - RULES
============================================================

------------------------------------------------------------
READ EACH FILE - HOW TO EXTRACT CONTENT

For each formative HTML file:
  - Read the filename, <title> tag, and the assessment-title in
    the header to confirm the unit number and skill the file covers.
  - Scan all 8 versions (V1-V8). Group them by skill cluster:
    V1-V2 often share a skill, V3-V4 another, V5-V6 another,
    V7-V8 another - but not always. Read each version task.
  - Summarize what students are actually asked to do across
    all 8 versions. This drives the description you write.
  - Note which unit section the content belongs to (for example,
    slope from points -> after the slope section; graphing lines ->
    after the graphing linear equations section; writing equations
    -> after the linear equation modeling section). This drives the
    timing label.

------------------------------------------------------------
WHAT TO CHANGE - FORMATIVE SECTION

Inside the formative section ("Assessment Methods by DOK Level"),
change these elements:

  - The name (link text) of each of the 16 assessment entries
  - The timing label (Can Be Assessed After Section X) of each
  - The description text of each
  - The 4 "What this tells the teacher" blurbs (one per DOK level)

Assessment entry names must be clean skill names only. Remove any
leading DOK number prefix from the displayed link text. For example,
write "Graph Tables and Intercepts" instead of "DOK 2.1 Graph
Tables and Intercepts." Apply this to all 16 formative assessment
entries. Do not remove or alter the DOK-bar labels.

------------------------------------------------------------
WHAT TO CHANGE - UNIT SHELL WHEN TEMPLATE UNIT DOES NOT MATCH

If the target unit from the formative files differs from the unit
shown in the assessment plan file, also update the plan shell so the
entire delivered file is a target-unit plan.

Update all of the following to the target unit:

  - <title>
  - Main <h1>
  - Any inferred-input comment lines that name the course unit,
    formative path, summative path, or spiral timing
  - Visible unit labels inside the formative section
  - Formative href values and filenames
  - Summative href values and filenames
  - Output filename
  - Any other visible or hidden unit-number references in the HTML

Path conversion rule for mismatch cases:
  - Preserve the relative path structure, but replace the old unit
    number with the target unit number.
  - Example:
      ../formative/unit1_formative/unit1_dok2-3.html
    becomes:
      ../formative/unit2_formative/unit2_dok2-3.html
  - Example:
      ../summative/unit1_summative/unit1_summative.html
    becomes:
      ../summative/unit2_summative/unit2_summative.html

Do not keep old-unit href values in a target-unit output.

Unit title rule for mismatch cases:
  - If a clear unit title is present in the formative files or their
    content, use it.
  - If no explicit unit title is provided, infer a concise title from
    the sixteen formative assessments and flag it in Issues needing
    review.
  - For Unit 2 formative files about slope, graphing lines, writing
    linear equations, comparing plans, model fit, and linear
    relationship creation/revision, a reasonable inferred title is
    "Linear Relationships."

Section outline rule for mismatch cases:
  - If the plan's section outline is clearly from the old unit, do
    not leave it unchanged as if it were the target unit.
  - Rewrite the section outline only as much as needed to align with
    the target unit skills inferred from the formative files.
  - Keep the existing HTML structure and style classes.
  - Because no separate unit outline was provided, label this as
    inferred in the QA report.

------------------------------------------------------------
DO NOT TOUCH - LOCKED ELEMENTS WHEN TARGET UNIT MATCHES TEMPLATE UNIT

When the assessment plan already matches the target unit, these
elements must be copied from the input plan exactly:

  - All href values (links stay character-for-character identical)
  - Section outline cards (titles, learning targets, I-cans,
    key representations, modeling opportunities)
  - Essential Standard
  - Learning Ladder table
  - Progress Tracking boxes
  - Summative Assessment Plan section
  - Holistic Rubric
  - DOK-bar labels (DOK 1 - Rungs 1-2, etc.)
  - Format lines (Format: 3-5 minute warm-up...)
  - Purpose lines (Purpose: DOK 1 reveals...)
  - CSS link tags, head order, MathJax config
  - All HTML structure outside the formative section

These locked-element rules are conditional. They do not allow an
old-unit template to remain old-unit when the formative files clearly
belong to a different target unit.

------------------------------------------------------------
DESCRIPTION FORMAT

Each assessment entry description must:
  - Open with one strong verb (not a weak verb - see below)
  - Cover 2-3 distinct skill bullets separated by semicolons
  - Be specific to what the file versions actually assess
  - End with a period

Example format:
  "Compute with integers, fractions, and decimals; apply sign
  rules across all four operations; use absolute value to find
  distance between two numbers."

Weak verbs - do not open descriptions with these:
  identify / describe / match / explain / show / list

------------------------------------------------------------
TIMING LABELS

Timing = the latest prerequisite section a student must have
completed before this assessment is appropriate.

Infer from the content of the file and the target unit section
sequence. If no unit outline was provided, infer a reasonable section
sequence from the sixteen formative files.

For Unit 2 linear relationships, likely timing clusters are:
  - Slope from points and rate of change -> after the slope/rate
    section
  - Graphing steps, graphing lines, and graph critiques -> after
    the graphing linear relationships section
  - Equation basics, writing equations, and equation-method analysis
    -> after the linear equations/modeling section
  - Comparing plans, model fit, recommendations, and data-model
    revision -> after the applications/model comparison section

If multiple skills appear in one file, use the latest section
required by any of the version groups.

------------------------------------------------------------
DESCRIPTION VERB RATIO

Opening verb of each description drives the ratio.
Target across all 16 descriptions:
  Modeling  (5-8): construct, formulate, build, design, model,
    represent, develop, create, generate, translate, establish
  Applying  (5-8): apply, use, predict, extend, solve,
    calculate, compute, evaluate, estimate, substitute,
    simplify, interpret, convert, adapt, classify
  Justifying (2-4): critique, assess, determine, verify,
    validate, analyze, conclude, reason, argue

Spread rule: no single DOK level should be all one verb type.
DOK 1-2 may lean applying; DOK 4 may lean modeling - but vary.

------------------------------------------------------------
WHAT-TELLS BLURBS

Each of the 4 "What this tells the teacher" blurbs must:
  - Be specific to the actual content of that DOK level's
    4 files, not a generic statement
  - State what teacher insight the data provides
  - Be 1-2 sentences

PART 2 - QUALITY PASSES - RUN ALL BEFORE DELIVERING
============================================================

PASS 0 - UNIT IDENTITY CHECK
  Determine TARGET UNIT and TEMPLATE UNIT and report both.
  Confirm the final output target unit matches the formative files.
  Confirm <title>, main <h1>, visible unit labels, formative paths,
  summative paths, and output filename all use the target unit.
  If target unit and template unit differed, confirm old-unit labels
  and old-unit paths were removed or converted.
  Example failure to catch: formative files are Unit 2, but final
  HTML still says Unit 1 or links to unit1_formative.

PASS 1 - LINK CHECK
  If TARGET UNIT and TEMPLATE UNIT matched:
    Compare all 16 href values in output against input.
    Confirm every href is character-for-character identical.
    Any change to an href is an error - flag and fix.

  If TARGET UNIT and TEMPLATE UNIT differed:
    Confirm all formative hrefs were converted to the target unit
    while preserving the relative path structure and DOK filenames.
    Confirm no old-unit formative or summative hrefs remain.

PASS 2 - COVERAGE CHECK
  Confirm 16 entries are present: 4 per DOK level.
  Confirm each entry has: name, timing label, description.
  Confirm 4 what-tells blurbs are present.

PASS 3 - DESCRIPTION VERB AUDIT
  List all 16 description opening verbs by DOK level.
  Tally: Modeling=X  Applying=X  Justifying=X
  Confirm M is 5-8, A is 5-8, J is 2-4.
  Confirm no single DOK level is all one verb type.
  Report counts - do not just say "compliant."

PASS 4 - ACCURACY CHECK
  For each of the 16 entries, confirm the name, timing,
  and description accurately reflect the content of the
  corresponding file as read. Flag any entry where the
  description does not match what the file versions assess.

PASS 5 - LOCKED/CONVERTED ELEMENTS CHECK
  If TARGET UNIT and TEMPLATE UNIT matched:
    Confirm nothing outside the formative section changed.
    Spot-check: Essential Standard, one I-can, one ladder rung,
    summative link, rubric first sentence - all identical to input.

  If TARGET UNIT and TEMPLATE UNIT differed:
    Confirm the plan shell was converted to the target unit.
    Confirm old-unit-specific section outline content was not left
    unchanged in a way that mislabels the old unit as the target unit.
    Spot-check: Essential Standard, one I-can, one ladder rung,
    summative link, rubric first sentence - each should either align
    with the target unit or be reported in Issues needing review.

PASS 6 - FORMATIVE NAME PREFIX CHECK
  Confirm all 16 formative assessment link names are clean skill
  names with no leading DOK number prefix. Examples of forbidden
  display names: "DOK 1.1 Coordinate Pairs and Axes," "DOK 2.1
  Graph Tables and Intercepts," "DOK 4.4 Compare and Recommend
  Plans." The corresponding href values must follow the link rule
  for the same-unit or mismatch case.

PASS 7 - OLD-UNIT RESIDUE CHECK
  If TARGET UNIT and TEMPLATE UNIT differed, search the complete
  output HTML for the old unit number and old unit path roots.
  For example, if converting Unit 1 template to Unit 2, search for:
    Unit 1
    unit1_
    /unit1_
    unit1_formative
    unit1_summative
  Any remaining old-unit residue is a failure unless it appears only
  in a clearly labeled QA comment explaining the conversion. Prefer
  no old-unit residue at all in the delivered HTML.

After the file, deliver a QA report:
  Pass 0-7 result for each
  Target unit and template unit
  Whether this was a same-unit rewrite or previous-unit conversion
  Verb counts (Modeling / Applying / Justifying)
  Issues fixed
  Issues needing review

COMMON FAILURE MODES
============================================================

1.  Leaving the old unit identity in the output when formative files
    clearly belong to a different unit
2.  Treating an old-unit plan as locked when it is only a template
3.  Preserving unit1_formative or unit1_summative links in a Unit 2
    output
4.  Changing href values in a same-unit rewrite
5.  Writing descriptions that describe the plan's old intent rather
    than what the actual file versions assess
6.  Timing labels that do not match the content of the file
7.  Weak opening verbs (identify / describe / explain / show)
8.  Verb ratio out of range (M or A outside 5-8, J outside 2-4)
9.  All four DOK 3 descriptions using error-analysis framing
10. Generic what-tells blurbs not tied to the actual files
11. Touching locked elements during a same-unit rewrite
12. Delivering only the changed section instead of the full file
13. Stopping to ask questions - read the files and infer
14. Missing QA report
15. Reporting verb counts without listing the actual verbs
16. Leaving leading DOK number prefixes in formative assessment
    display names, such as "DOK 2.1 Graph Tables and Intercepts"
17. Delivering a file whose filename says one unit but whose HTML
    title, h1, or links point to another unit
