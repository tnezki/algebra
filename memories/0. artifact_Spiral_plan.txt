Spiral Structure and Question Source Rules

SPIRAL TERMINOLOGY (locked)

  Current unit  — the unit being taught now (e.g., Unit 1)
  Last unit     — one unit back (e.g., Unit 0B)
  Mastery unit  — two units back (e.g., Unit 0A) This is the unit being formally assessed for long-term retention in this rotation.

PRACTICE SET SYSTEM (locked)

  All four practice sets (PS1–PS4) for a section are built
  in a single PM session using three bank uploads (current,
  last, mastery) and the current unit's schedule CSV.

  PS1 = Day 1 practice set
  PS2 = Day 2 activity (Activity 1)
  PS3 = Day 3 activity (Activity 2)
  PS4 = Extra Practice (distributed outside the 3-day structure)

  Each set follows the 4 / 8 / 4 structure:
    4 questions from current section
    8 questions from mastery unit
    4 questions from last unit

DIAMOND / RECTANGLE ROTATION (WARMUP SLOT 4)

Slot 4 of every warmup is always a generated figure problem,
never pulled from the bank. Type rotates by unit.

  Units 0A, 0B, 1  →  Diamond Problem only
  Unit 2            →  Diamond Problem + generic rectangle (multiply)
  Units 3–8         →  Full rotation: Diamond Problem /
                        generic rectangle (multiply) /
                        factor generic rectangle

DIAMOND PROBLEM — 6 VARIATIONS
  Four positions: top (product) / bottom (sum) /
                  left factor / right factor
  Two positions are blank; student fills them in.

  V1  Given: left + right factors  →  Find: product + sum      (easiest)
  V2  Given: product + left        →  Find: right factor + sum
  V3  Given: product + right       →  Find: left factor + sum
  V4  Given: left factor + sum     →  Find: product + right
  V5  Given: right factor + sum    →  Find: product + left
  V6  Given: product + sum         →  Find: left + right       (hardest)

  Progression: begin with V1 in early units, advance toward
  V6 as factoring develops in Units 3+.

All three types are generated by graph_tool.py:
  make_diamond()           →  Diamond Problem (all six variations)
  make_rectangle_model()   →  generic rectangle (multiply or factor)
  Blank cells passed as '' for student-fill positions.

OTHER ARTIFACTS

PROGRESS TRACKER (per unit, student-facing)
  8 questions per DOK level (DOK 1/2/3/4) = 32 questions
  AI-derived from bank questions and unit I-cans
  Not direct copies — new questions that represent the unit's
  learning targets at each DOK level

FORMATIVE ASSESSMENTS (16 per unit)
  4 per DOK level, matching assessment plan structure
  8 versions per file: V1–V4 same-day / V5–V6 first retake /
    V7–V8 second retake
  Built by number-swapping or lightly rewriting bank items
  tagged <!-- assessment-grade --> items are preferred source
  Not independent draws — variants of bank items
  and/or
  Each item covers two adjacent ladder rungs as a multi-part
  question — Part a addresses the lower rung, Part b the upper.
  Built by combining two bank items that sit on adjacent rungs,
  then rewriting as a single coherent multi-part question.

SUMMATIVE ASSESSMENT (per unit)
  DOK 1–3 only — DOK 4 is not assessed on the summative
  45-minute paper-only time limit
  10–12 questions per version
  6 versions in one HTML file:
    V1–V3 same-day parallel forms (anti-cheat)
    V4–V6 retake / makeup forms
  Items built from tagged <!-- assessment-grade --> bank items:
    Mostly: number-swap (same structure, new numbers)
    Mostly: light rewrite (change phrasing or context)
    Occasionally: switch order information is presented
    Occasionally: merge 2 questions into 1

INVESTIGATIONS
  Lab-style tasks. No bank questions used.
  Built independently of the bank system.

BANK DEMAND ANALYSIS (why bank sizing matters)

Per section, approximate draws across all three unit roles:

  Current section own use:           ~22 draws
  Last unit role (next unit):        ~19 draws per section (avg)
  Mastery unit role (unit + 2):      ~36 draws per section (avg)
  Total demand per section:          ~77 draws

  Last and mastery draws are pooled at the unit level and
  distributed across all 5 sections of the current unit.
  Some questions in high-demand DOK levels (DOK 2–3 mastery)
  will appear in multiple sections as number-swap variants.

Number-swappable items give ~3–4 variants per structural item.
Need ~25–30 structurally distinct items per section to cover
77 draws without same-section repetition.

TARGET BANK SIZE:
  DOK 1: 12–16 structurally distinct items
  DOK 2: 10–12 items
  DOK 3: 6–8 items
  DOK 4: 4–6 items
  Section total: ~32–42 items
  Unit total:    ~160–210 items

QUESTION ASSIGNMENT SYSTEM:
  All bank draws are pre-assigned in unit schedule CSVs
  (one CSV per unit). Upload the current unit's schedule
  alongside the PM and all three bank HTML files.
  The schedule encodes for each slot:
    q_id        — specific question to use
    bank_unit   — which bank HTML to find it in
    usage_type  — exact (copy verbatim) or
                  number_swap (same structure, new numbers)

QUESTION SOURCE RULES BY ARTIFACT

  Practice sets (PS1–PS4):   exact or number-swap from bank
                              (assignments pre-determined by
                               unit schedule CSV)
  Warmup slots 1–3:          exact or number-swap from bank
                              per schedule CSV
  Warmup slot 4:             generated by graph_tool.py
                              (never from bank)
  Examples:                  exact from bank (DOK 1–3,
                              current section)
  YTIs:                      AI-derived from examples
                              (same structure, new numbers)
  Future Task:               AI-derived (DOK 4 formative
                              variant, embedded in Notes)
  Exit tickets:              AI-derived from today's practice
                              content (NOT from bank)
  CYU:                       AI-derived summary of PS4 content
                              (NOT from bank)
  Progress tracker:          AI-derived from bank + I-cans
                              (NOT direct copies)
  Formatives:                number-swap / light rewrite of
                              bank items (prefer AG-tagged)
  Summatives:                number-swap / light rewrite of
                              bank items (prefer AG-tagged)

════════════════════════════════════════════════════════════════

SESSION UPLOAD RULES

  Practice sets (PS1–PS4) + exit tickets + CYU:
    PM + unit[#]_schedule.csv + current bank +
    last bank + mastery bank

  Warmups:
    PM + unit[#]_schedule.csv + current bank +
    last bank + mastery bank
    (no assessment plan needed)

  Notes (examples + YTIs + Future Task):
    PM + unit[#]_schedule.csv + current bank

  Formatives:
    PM + current bank (+ graph_tool if figures needed)

  Summative:
    PM + current bank (+ graph_tool if figures needed)

  Progress Tracker:
    PM + assessment plan + current bank

NOTES

  Exit tickets and CYUs are never pulled directly from the
  bank — they are generated to reflect what was covered.

  The Day 1 warmup prior knowledge questions require thematic
  judgment: the schedule CSV marks these rows with
  notes = prior_knowledge as a reminder to verify the selected
  questions are prerequisite skills for the upcoming section.

  PS1–PS4 and their exit tickets are built in a single PM
  session per section. The CYU is a separate HTML file.

  "Identical version" principle: bank items are the canonical
  specification. Artifacts copy them or generate variants.
  They do not invent independently.
