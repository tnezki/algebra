VERSION FAMILIES — REQUIRED STRUCTURE

Each of the 16 formative HTML files contains 3 version families.

V1–V4 — ASSESSMENT-DAY PARALLEL FORMS
  Purpose: reduce copying on the day of assessment.
  Same question family. Different numbers, context, or values.
  All 4 must be genuinely distinct — not trivially the same.

V5–V6 — FIRST REASSESSMENT / MAKEUP PAIR
  Purpose: absent students or first reassessment.
  DIFFERENT question family from V1–V4.
  Same skill target and DOK level as V1–V4.
  The two versions parallel each other (different numbers).

V7–V8 — SECOND REASSESSMENT / MAKEUP PAIR
  Purpose: second reassessment or additional retake.
  DIFFERENT question family from both V1–V4 and V5–V6.
  Same skill target and DOK level.
  The two versions parallel each other (different numbers).

A student who took V2 should see V5 as a fresh question family.
A student who took V5 should see V7 as another fresh family.

Not allowed:
  — V5–V8 as simple number swaps of V1–V4.
  — V7–V8 as simple number swaps of V5–V6.
  — Changing the DOK level or skill between families.

CONTENT STRUCTURE OPTIONS (use whichever fits the item):

Option 1 — Scenario + ordered parts:
  <div class="scenario">A gym charges a \$12 startup fee and \$4 per visit.</div>

  <ol type="a">
  <li>Evaluate the expression for $v=6$.</li>

  <ol type="a">
  <li>Show each step of substitution and simplification.</li>
  <li>Identify which operation must be applied first and why.</li>
  </ol>

Option 3 — Error analysis (DOK 3):
  <p>A student simplifies $3(2x-4)+5$ and writes $6x-7$.</p>
  <ol type="a">
  <li>Identify the error. Show the correct step.</li>
  <li>Explain in one sentence why the student's approach fails.</li>
  </ol>

Option 4 — Design/model task (DOK 4, 5–10 min):
  <div class="scenario">A student has \$32. A sandwich costs \$7; each snack costs \$3.</div>
  <ol type="a">
  <li>Write an inequality for the number of snacks $s$ with one sandwich.</li>
  <li>Solve the inequality and interpret the solution set.</li>
  <li>Recommend a reasonable number of snacks and justify your choice.</li>
  </ol>

DOK AUTHENTICITY — ENFORCE IN EVERY VERSION

DOK 1: Recall, recognition, single-step procedure, simple
  graphing/reading. No strategic choice required.
  FAIL: item requires interpretation beyond the procedure.

DOK 2: Apply a concept, multi-step execution, representation
  connection, interpretation in context.
  FAIL (too low): pure computation with no interpretation.
  FAIL (too high): requires analysis or critique.

DOK 3: Strategic reasoning — critique an error, compare two
  methods, analyze structure, construct a strategy, find a
  mismatch between representations.
  FAIL: reasoning is pre-filled for the student (table with
  categories given, error explained in the prompt).
  Student must do the analysis, not just recognize a label.

DOK 4: Extended reasoning — design, model, synthesize, revise,
  recommend. Completable in 5–10 minutes on paper.
  FAIL: longer than 10 minutes or requires multi-day work.
  FAIL: no genuine design or synthesis demand (just DOK 2).

10-second test (DOK 2+):
  If a strong student can answer by scanning in under 10 seconds
  without computing, it is too weak. Revise before delivery.

CATALOG UPDATE — CREATE CSV FILE AND SUMMARIZE IN CHAT AFTER QA LOG

Create a separate CSV file named:

unit[#]_catalog_update.csv

This file is required for every formative build. It tracks exactly how bank items were used in the formative package and is designed to be pasted or imported into master_catalog.xlsx.

CSV columns, in this exact order:

q_id,artifact_type,artifact_unit,artifact_section,artifact_day,artifact_slot,usage_type,combine_with

Required values:

q_id
The original bank item ID used as a source.
Example: 2-S1-DOK1.03

artifact_type
Always: formative

artifact_unit
The unit number.
Example: 2

artifact_section
The source bank section or inferred section label.
Example: S1 or 2.1

artifact_day
Use — unless a specific day is supplied by an assessment plan.

artifact_slot
The formative file slot and version family.
Examples:
dok1-1 V1-4
dok1-1 V5-6
dok1-1 V7-8

usage_type
Use one of:
number-swap
context-swap
structure-adapt
combine

```
number-swap = same question family with changed values only.
context-swap = same mathematical structure with a changed context.
structure-adapt = same skill target but changed question structure.
combine = two bank items are intentionally bridged into one formative family.
```

combine_with
Use — unless usage_type is combine.
If usage_type is combine, list the other bank item ID used in the paired bridge.

ROW RULES

Create one row for every bank item used in every version family.

Each formative slot normally has at least 3 catalog rows:

one row for V1–V4
one row for V5–V6
one row for V7–V8

If a version family uses Mode B or otherwise combines two bank items, include two rows for that family:

[lower/source ID] with combine_with = [paired ID]
[paired ID] with combine_with = [lower/source ID]

For a standard 16-slot build with no combine rows, the CSV will usually contain 48 data rows:

16 slots × 3 version families = 48 rows

If combine rows are used, the CSV may contain more than 48 rows.
