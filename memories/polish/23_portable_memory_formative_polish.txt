FORMATIVE ASSESSMENT POLISH PORTABLE MEMORY - TWO PASS VERSION
================================================================

PURPOSE

Use this portable memory to polish a formative assessment package that has already been built from an assessment bank. This is not a rebuild. It is a targeted two-pass polish focused only on:

1. Technical MathJax / corruption errors.
2. Bad questions / weak student-facing assessment items.

This PM is pared down from the uploaded bank polish PM, bad-question pass PM, and MathJax pass PM. It is adapted for the formative package format: 16 HTML files, each with 8 versions, plus generate_graphs.py, figures/, and an optional catalog update CSV.

================================================================
READ ORDER - MANDATORY BEFORE ANY OUTPUT

1. Read THIS document completely.
2. Read the uploaded formative package or extracted formative folder completely.
   - Read all 16 HTML files.
   - Read every version page in every file.
   - Read every table, equation, prompt, image reference, and visible note.
3. Read generate_graphs.py completely when provided.
   - Check all graph calls used by the formative HTML.
   - Check title=, xlabel=, ylabel=, legend labels, and other math labels.
4. Read the catalog update CSV if provided.
   - Use it only for source traceability and to confirm what bank item each formative family came from.
   - Do not change the catalog unless a source mapping truly changes.
5. If the original build PM, source bank, or assessment plan is also uploaded, use them only to verify alignment or repair a flagged issue. Do not rebuild from them.

Do not begin final output until all files are read and the corrected ZIP is ready.

================================================================
THIS FILE IS THE SINGLE SOURCE OF TRUTH FOR THIS POLISH

If prior memory, saved workflow, older PMs, or generic habits conflict with this file, follow this file.

This polish has exactly two content/technical passes:

PASS A - TECHNICAL MATHJAX / CORRUPTION
PASS B - BAD QUESTIONS / CONTENT QUALITY

Do not run the full seven-pass bank-polish system unless the user explicitly asks for it.

================================================================
WHAT POLISH MEANS

POLISH DOES:
- Fix broken MathJax, raw reserved characters inside math, unbalanced LaTeX environments, corrupted \frac or \right, and unescaped currency dollars.
- Fix bad questions that fail the 10-second test or the bad-pattern audit.
- Fix graph titles that reveal an answer students are asked to produce.
- Fix figure generation code only when needed for a flagged issue.
- Preserve the formative package structure.
- Preserve version-family intent: V1-V4 assessment-day family, V5-V6 first reassessment/makeup family, V7-V8 second reassessment/makeup family.
- Produce a corrected ZIP.

POLISH DOES NOT:
- Rebuild the formative package from scratch.
- Replace valid items merely because another item is prettier.
- Change file names, DOK slot names, or version numbering.
- Change DOK level unless an item clearly fails its assigned DOK demand.
- Add new version pages.
- Remove version pages.
- Redesign CSS or page layout.
- Add custom classes outside the locked formative template.
- Rewrite working items that are not flagged by a pass.
- Modify graph_tool.py source lines above the append marker.

MINIMUM CHANGE PRINCIPLE:
Every fix must be the smallest change that resolves the flagged issue.
If one dollar sign is wrong, fix only that dollar sign.
If one graph title leaks the answer, clear only that title parameter.
If one prompt is too visually obvious, add the smallest reasoning requirement needed to make it valid.
If one version family has a weak variant, fix that variant without changing the other versions unless the family pattern itself is flawed.

LOCKED FORMATIVE HTML RULES

Each HTML file must still contain exactly 8 version pages:

Allowed body classes are the locked formative classes:
page, header-row, assessment-title, name-line, directions, task, qnum, scenario, note, word-bank, graph-block, graph-md, graph-sm, graph-lg, values, data-table, left, tight.

Do not introduce unapproved wrapper classes such as container, card, formative-card, formative-header, source-note, workspace, problem-card, or item-card.

================================================================
PASS A - TECHNICAL MATHJAX / CORRUPTION

Run this pass on every formative HTML file.
Exclude existing QA comments from scans when counting student-visible issues.

A1. Corruption scan

Scan raw bytes and raw strings in student-visible content.

Byte-level checks:
- bytes([0x0c]) in body content -> likely broken \frac.
- bytes([0x0d]) in body content -> likely broken \right.

String-level checks:
- \rac not preceded by f -> incomplete \frac.
- \ight not preceded by r -> incomplete \right.
- Unescaped currency dollar immediately before a digit outside math mode, such as $5 or $120.
- Wrong MathJax delimiters in body text: \(, \), \[, \].

Count legitimate LaTeX occurrences for plausibility:
- \frac
- \left
- \right

Required result before PASS:
- x0c hits = 0
- x0d hits = 0
- broken \rac hits = 0
- broken \ight hits = 0
- bare currency $[digit] outside math = 0
- wrong delimiters = 0

Common fixes:
- bytes([0x0c]) in a formula -> replace with \frac.
- bytes([0x0d]) in a formula -> replace with \right.
- \rac -> \frac.
- \ight -> \right.
- $5 as currency -> \$5.
- \(x+1\) -> $x+1$.
- \[x+1\] -> $$x+1$$.

A2. MathJax final scan

For each HTML file, check:

1. Bare currency dollars:
   - No unescaped $ before a digit outside math mode.

2. Wrong delimiters:
   - No \(...\) or \[...\] in student-visible body content.

3. Raw < or > inside math delimiters:
   - Replace $x<3$ with $x\lt 3$.
   - Replace $x>0$ with $x\gt 0$.
   - Do not change >=, <=, ≥, or ≤ unless they are malformed.

4. LaTeX environment balance:
   - Every \begin{...} has a matching \end{...} of the same environment.
   - Check at minimum: aligned, align, array, cases, matrix, pmatrix, bmatrix, vmatrix, split, gathered, alignedat.
   - No unmatched opener, unmatched closer, or crossed nesting.
   - Common fix: add only the missing \end{aligned} before the closing $$.

5. MathJax config:
   - window.MathJax config must appear before the MathJax CDN script.
   - CDN should use cdn.jsdelivr.net.

PASS A QA LOG FORMAT:

For each HTML file, record:
- File name
- x0c hits
- x0d hits
- broken \rac hits
- broken \ight hits
- bare currency hits
- wrong delimiter hits
- legitimate \frac count
- legitimate \left count
- legitimate \right count
- raw < or > inside math
- environment balance errors
- config before CDN: YES/NO
- CDN correct: YES/NO
- fixes applied
- result: PASS/FAIL

The package cannot pass while any file still has a FAIL line.

PASS B - BAD QUESTIONS / CONTENT QUALITY

Run this pass on every version page in all 16 formative HTML files.
Use the DOK level from the file name:
- unit[#]_dok1-[slot].html -> DOK 1
- unit[#]_dok2-[slot].html -> DOK 2
- unit[#]_dok3-[slot].html -> DOK 3
- unit[#]_dok4-[slot].html -> DOK 4

Apply the 10-second test to every DOK 2, DOK 3, and DOK 4 version.
Apply bad-pattern checks to every version at every DOK level where relevant.

B1. 10-second test for DOK 2+

Ask:
Can a strong student produce a plausible answer in under 10 seconds by scanning labels, titles, table headers, graph shape, or visible answer cues without doing the intended reasoning?

If yes, the version fails. Fix with the smallest change that restores the intended DOK demand.

Important distinction:
A fast but genuine procedure is OK.
A visible answer or shape-only response is not OK.

B2. Bad-pattern audit

Check every version for these patterns:

5a - Answer given by column labels
A table header gives away what students are supposed to determine.
Fix by removing the revealing header or asking for justification/evidence that cannot be read directly from the header.

5b - Answer visible in graph
The graph labels a point, intercept, vertex, intersection, guide line, or other value students are asked to find.
Fix by correcting the figure or the prompt. If a new/corrected figure is needed, use graph_tool functions and preserve styling rules.

5b-graph-title - Equation or answer in graph title
For every <img src="figures/..."> reference, find the graph call in generate_graphs.py.
If title= contains an equation, zeros, vertex, multiplier, rate, family name, or other specific answer students are asked to identify or produce, it is a violation.
Applies at all DOK levels.
Allowed titles: title='' or a plain generic descriptor such as 'Graph A', 'Model comparison', or 'Data display'.
Exception: an equation in the title is allowed only when the item text already gives that equation and explicitly asks students to verify or use that named equation.
Fix by changing only the title= parameter. Do not change the filename.

5c - Answer encoded in question text or notation
The prompt restates the answer through wording or notation.
Fix by removing the embedded answer and asking for the finding separately.

5d - Cross-reference to another item
The prompt depends on a previous version/page/item.
Fix by embedding all needed context in the current version.

5e - Answer restated in question
The question states the answer and asks students to explain or confirm it.
Fix by asking students to determine the answer first.

5f - Adjacent or same-file versions use stale formats
For formative packages, do not treat V1-V4 parallelism as a 5f violation by itself. V1-V4 are supposed to be the same assessment-day family.
Do flag 5f only when:
- V5-V6 are merely number swaps of V1-V4,
- V7-V8 are merely number swaps of V5-V6 or V1-V4,
- or a single version page has back-to-back subparts that repeat the same task shell without increasing reasoning.
Fix while preserving the required family structure.

5g - Trivial visual classification
The item asks only for family, growth/decay, or shape identification and the visual makes it obvious.
Fix by adding a required evidence step, parameter estimate, rate comparison, constraint, or justification using table/graph features.

5j - Mismatch critique depends on missing or prior work
A mismatch item asks students to critique a representation but does not provide all needed representations in the current version.
Fix by embedding the missing table, equation, graph description, or claim.

5k - Scaffolded DOK 3
A DOK 3 item pre-labels the reasoning category or tells students exactly what type of reasoning to use.
Fix by removing the pre-categorizing scaffold while keeping enough information to reason.

5m - Pre-answered table
The prompt asks students to complete, fill in, find, or record table values, but the answer cells are already filled.
Fix by clearing only the answer cells. Keep header values and stated givens.

5n - Context plausibility failure
The numbers produce unrealistic outputs for the stated context.
Fix the smallest number, multiplier, or time unit while keeping the same mathematical structure.

5o - Template-only / non-actionable shell
The prompt names a task type or broad skill but does not provide enough concrete mathematical input for students to begin.
Fix by adding only the missing concrete input: equation, table, data, graph, flawed claim, two approaches, anchor values, or required products.

B3. Version-family integrity after fixes

After fixing bad questions, recheck each HTML file:

- V1-V4 remain one assessment-day family with genuinely distinct numbers/context/values.
- V5-V6 remain a parallel reassessment pair.
- V7-V8 remain a second parallel reassessment pair.
- V5-V6 are a different question family from V1-V4.
- V7-V8 are a different question family from both V1-V4 and V5-V6.
- DOK level remains aligned to the file name.

If a bad-question fix accidentally turns V5-V8 into a number swap of V1-V4, fix again.

B4. Graph handling during bad-question fixes

Do not modify graph_tool.py source lines above the append marker.

If clearing an answer-leaking title in an existing graph call:
- Change only title=.
- Keep the same filename.
- Record the correction in the QA log.

If a new or corrected figure is required:
- Append a new graph block below all existing appended graph code.
- Use graph_tool functions.
- Use a new unique filename unless the change is only a title= correction.
- Reference the new filename in the fixed HTML.
- Do not manually override graph styling.

Graph labels containing math must use LaTeX strings, such as r'$2x+3$', not plain '2x+3'.

B5. PASS B QA LOG FORMAT

For each HTML file, record:
- File name
- DOK level
- 10-second failures: list or NONE
- Bad patterns 5a-5k: list or NONE
- Graph title violations: list or NONE
- Pre-answered tables 5m: list or NONE
- Context plausibility 5n: list or NONE
- Template-only shells 5o: list or NONE
- Version-family integrity: PASS/FAIL
- Fixes applied: list or NONE
- Graph title corrections in py: number or NONE
- New figure blocks added: list or NONE
- Result: PASS/FAIL

The package cannot pass while any file still has unresolved bad-question findings.
