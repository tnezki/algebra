GRAPH AND TABLE WORKSPACE RULES

Graphs serve two different purposes. Know which one
applies before deciding whether to include a graph.

Type A — Evidence Graph
  The graph contains information students need to answer.
  Examples: reading intercepts, identifying mismatches,
  interpreting slope, comparing representations.
  Include when the question requires reading a graph.

Type B — Workspace Graph
  The graph is not evidence — it is mathematical workspace
  for students to plot, sketch, model, or represent.
  Examples: plot a point, graph a relationship,
  create a model, compare two plans.
  Provide a blank graph whenever graphing is part of the task.
  Do not make students draw axes from scratch.

Graphs are not scarce.
  Use graphs whenever they improve evidence, communication,
  modeling, or student workspace.
  Do not minimize graphs to reduce figure count.
  Represent all four: graphs / tables / equations / contexts
  across each section.

Blank tables as scaffolds:
  If a student is expected to create, extend, compare,
  or organize a relationship, provide a blank table.
  Blank tables reduce transcription load without reducing
  mathematical reasoning.
  Use especially on DOK 2 modeling and DOK 3-4 tasks.

DOK 4 scaffolds:
  DOK 4 requires transfer and decision-making.
  DOK 4 does NOT require building every representation
  from scratch.
  Provide blank graphs, blank tables, or partially
  completed representations when appropriate.
  Students should spend time reasoning — not drawing axes.

════════════════════════════════════════════════════════════════

QUESTION QUALITY RULES

RULE 1 — 10-second test
  If a strong student can answer by scanning the question
  in under 10 seconds without computing or reasoning,
  the item is DOK 1 regardless of its label.
  Apply to every DOK 2+ item before finalizing.
  DOK 1 items are exempt — recall is correct there.

RULE 2 — DOK level must match cognitive demand
  DOK 1: recall, recognition, single-step retrieval
  DOK 2: apply a procedure, connect representations,
          solve a routine problem
  DOK 3: construct reasoning, critique a claim with
          evidence, justify a conclusion, analyze
          structure across representations
  DOK 4: design, create, synthesize, model an unfamiliar
          situation, make and justify a recommendation
          5-10 minutes maximum — no projects, no multi-day

RULE 3 — DOK 3 variety
  Rotate across the ~4 items. Do not default to all
  error analysis.
  Formats: justification / strategy construction /
  representation analysis / reasonableness argument /
  cross-representation comparison / critique and revise.
  Representation mismatch tasks are a preferred DOK 3
  structure — see Mismatch Rule below.

RULE 4 — DOK 4 scope
  5-10 minutes only. Must require transfer.
  Not solvable by routine procedure application.
  Design / modeling / decision-making tasks.
  Provide scaffolds (blank graphs, blank tables) to
  reduce formatting burden without lowering demand.

RULE 5 — Variety within each DOK block
  No two adjacent items same task format.
  Rotate: table / graph / equation / context /
  written explanation.
  At least one written explanation item per DOK 3 block.

RULE 6 — Self-contained items
  Every item stands alone. No cross-references ever.
  Never: "Use the graph from Problem 3..."
  Never: "Use your answer from the previous question..."
  Reshow any needed graph or table within the item.

RULE 7 — Classification requires multi-representation evidence
  Do not create tasks that ask students to classify
  function families based solely on graph shape.
  Classification must require evidence from rate of change,
  intercepts, tables, equations, contexts, or behavior.
  Avoid trivial visual sorting tasks.

RULE 8 — Representation mismatch (preferred DOK 3 structure)
  When appropriate at DOK 3, provide two representations
  (graph + table, graph + equation, or table + equation)
  with one intentional mismatch.
  Ask students to:
  1. Identify the first input where the mismatch occurs.
  2. Explain how they know.
  3. Describe how the incorrect representation should
     be revised.
  This naturally requires evidence, comparison, critique,
  and revision — strong DOK 3 structure.

════════════════════════════════════════════════════════════════

BAD QUESTION PATTERNS — NEVER USE THESE

5a — Answer given by column labels
  Bad: Table labeled 'hours' and 'pay' — "which is input?"
  Fix: Generic labels. Require reasoning from relationship.

5b — Answer visible in the graph
  Bad: Identify a labeled or highlighted point.
       Predict a value shown by a dashed guide line.
  Fix: No coordinate labels on data points.
       No guide arrows. No highlighted answer points.

5c — Answer stated in text immediately above
  Bad: Defines a term then asks student to identify it.
  Fix: Require application — not instant recall.

5d — Cross-reference to another item
  Bad: "Use the graph from Problem 3..."
  Fix: Every item self-contained. Reshow graph or table.

5e — Answer given in the question text
  Bad: "Point is at (4,0). Identify the x-intercept."
  Fix: Give information. Require reasoning from definitions.

5f — Adjacent items same task type
  Bad: All DOK 2 items are computation problems.
  Fix: Vary format across the block.

5g — Trivial visual sort or classification
  Bad: Visually obvious families — sort by shape alone.
  Fix: Ambiguous distractors. Multi-representation evidence.

5j — Mismatch critique with cross-reference
  Bad: "Does the graph from Problem X match the table?"
  Fix: Graph and table on same item. One deliberate error.
       Ask which input first shows the mismatch and why.
