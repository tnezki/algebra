WHAT POLISH MEANS — READ THIS FIRST

Polish is NOT a rebuild. Polish is a targeted scan-and-fix.

POLISH DOES:
  ✓ Fixes corruption, broken MathJax, broken tables
  ✓ Fixes items that fail the 10-second test or bad patterns
  ✓ Fixes DOK miscategorizations
  ✓ Fixes missing figures on items that require them
  ✓ Fixes figure generation code (labels, LaTeX strings)
  ✓ Fixes DOK3 format overuse violations
  ✓ Fixes DOK4 type combination duplicates
  ✓ Fixes currency escaping
  ✓ Fixes QA LOG contradictions or missing entries
  ✓ Fixes structural HTML errors (broken tables, wrong wrapper)

POLISH DOES NOT:
  ✗ Rewrite items that are not flagged by a pass
  ✗ Add new items to increase count
  ✗ Remove items that are merely imperfect but valid
  ✗ Change task names, problem numbers, or section structure
  ✗ Rewrite working DOK 3 or DOK 4 items just to vary them
  ✗ Touch graph_tool.py source lines — append only

MINIMUM CHANGE PRINCIPLE:
  Every fix must be the smallest change that resolves the issue.
  If only the opening verb of a question is wrong, fix only
  the opening verb. Do not rewrite the whole question.
  If only one table cell is wrong, fix only that cell.
  If a figure label needs LaTeX, fix only the label string.

PASS 4 — DOK LEVEL AUDIT

For every DOK 2+ item apply the 10-second test:
  If a strong student can answer by scanning in under
  10 seconds without computing or reasoning → DOK 1 demand.

For every item check bad patterns 5a–5o:
  5a: answer given by column labels
  5b: answer visible in graph (labeled point, guide line)
  5b-graph-title: equation or answer in graph title=
  5c: answer encoded in question text or notation
  5d: cross-reference to another item
  5e: answer restated in question
  5f: adjacent items same format
  5g: trivial visual classification
  5j: mismatch with cross-reference
  5k: scaffolded DOK 3 (pre-categorizing table column)
  5m: pre-answered table (answer cells already populated)
  5n: context plausibility failure (values unrealistic)
  5o: template-only / non-actionable task shell

5b-graph-title detail: For every figure src= in the file,
  find the matching graph call in generate_graphs.py and
  check its title= parameter. If the title contains the
  equation, zeros, factored form, vertex, or any specific
  answer the item asks the student to produce → VIOLATION.
  Applies at ALL DOK levels — DOK 1 is not exempt.
  ALLOWED: title='' or a plain-text generic descriptor.
  Exception: a title may show an equation ONLY when the item
  explicitly directs students to check their work against it.
  Fix: change title= to '' or a generic descriptor in
  generate_graphs.py. Do not change the filename.
  The figure will be overwritten when user re-runs the script.

5m detail: If item says "complete the table," "fill in,"
  or equivalent, but the answer cells in the HTML are already
  populated → VIOLATION. Smallest fix: clear the pre-filled
  answer cells, keeping only header values and stated givens.

5n detail: If numeric values in a context item produce outputs
  implausible for the stated real-world situation → VIOLATION.
  Fix: adjust starting value, multiplier, or time unit to
  keep outputs realistic without changing math structure.


5o detail: If an item reads like a template for the item writer
  instead of a usable student-facing problem → VIOLATION. This
  applies at ALL DOK levels. It often appears in DOK 4 cards
  that include the type label, generic constraints, and
  performance note, but it can also appear in DOK 2 or DOK 3
  comparison, critique, method-choice, or cross-representation
  items that omit the actual equation/problem, evidence, two
  approaches, flawed model, context, graph use, anchor values,
  or specific representations students need. Strip away the
  reusable boilerplate; if no exact mathematical work remains,
  fix the item by adding the missing concrete input using minimum
  change. A valid item may be open-ended, but it must still give
  students enough exact mathematical material to begin working.

List every finding:
  [ID]: [pattern or issue]

For each finding: fix or justify leaving it.
If fix changes the item, note the change.

  RESULT: PASS / FAIL

COMMON POLISH FAILURE MODES — DO NOT DO THESE
════════════════════════════════════════════════════════════════

1.  Rewriting items that are not flagged by any pass.
2.  Adding new items not needed to fix a specific problem.
3.  Changing problem numbers or section structure.
4.  Modifying graph_tool.py source lines — append only.
5.  Regenerating existing figures — append new blocks only.
6.  Reusing an existing figure filename for a new figure.
7.  Filling QA LOG summary counts independently rather than
    deriving them from the item-by-item lists.
8.  Writing PASS in the log before all corruption counts
    are confirmed zero.
9.  Fixing DOK3 format violations by rewriting the strongest
    items — fix the weakest or most substitutable one.
10. Treating a borderline item as a violation — only fix
    clear failures. Document borderline items as notes.
11. Delivering without a ZIP — always ZIP even if no new
    figures were added.
12. Plain-text math in graph label strings — always r'$...$'.
13. Using an HTML table for an area-model mismatch item.
    Area model mismatches → make_rectangle_model (Type 7).
    Expression-vs-table mismatches → table.values.
14. Applying the minimum-change principle to the QA LOG
    but not to content fixes — both require minimum change.
15. Leaving an equation in a graph title= when the item asks
    the student to find or write that equation (5b-graph-title).
    Fix: change title= to '' or a plain-text generic descriptor
    in generate_graphs.py. Never change the filename.
    This applies at ALL DOK levels — DOK 1 is not exempt.
16. Classifying a pre-answered table as a "borderline" case —
    if the item says "complete the table" and all cells are
    already filled, it is a clear 5m violation. Clear the cells.
