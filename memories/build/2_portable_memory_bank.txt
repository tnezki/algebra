AVAILABLE GRAPH TYPES (v12):

  Type 1  — make_standard_graph(ax, functions, title='')
    Standard ±10 coordinate plane. For algebra, parent functions,
    transformations, intersections.
    functions: list of dicts with 'expr', 'deriv', 'color', 'label'

  Type 2  — make_context_graph(ax, functions, xmin, xmax, ymin,
              ymax, xlabel, ylabel, title='')
    Custom axis ranges for real-world problems. Q1-oriented.

  Type 3  — make_number_line(ax, intervals, xmin=-10, xmax=10)
    Inequalities, absolute value, domain, range.
    intervals: list of dicts with 'start', 'end', 'start_open',
    'end_open', 'direction' ('left'|'right'|None), 'color'

  Type 3b — make_number_line_blank(ax, label=None, xmin=-10,
              xmax=10)
    Blank number line — student plots on it.
    label: optional LaTeX string shown at top

  Type 4  — make_2x2_grid(functions_list, titles=None)
    Four coordinate planes in one 504x504 figure.

  Type 5  — make_3x1_grid(functions_list, titles=None)
    Three coordinate planes side by side.

  Type 6  — make_4x1_grid(functions_list, titles=None)
    Four coordinate planes in a row.

  Type 7  — make_rectangle_model(row_labels, col_labels,
              cell_values, filename)
    Area model / generic rectangle.
    Any cell can be '' for blank — student fills it in.

  Type 8  — make_diamond(top, left, right, bottom, filename)
    Diamond problem. Any cell can be '' for blank.

  Type 9  — make_2x1_grid(functions_list, titles=None)
    Two coordinate planes side by side.

  Type 10 — make_piecewise_graph(ax, pieces, title='',
              dot_scale=0.65)
    Standard ±10 plane. Open/closed dots auto. Arrows at edges.
    pieces: list of dicts with 'expr', 'deriv', 'domain',
    'include_left', 'include_right', 'arrow_left', 'arrow_right'

  Type 11 — make_unit_circle_blank(filename)
             make_unit_circle_angles(ax_angle_deg, show_coord,
               filename)
    Unit circle. Valid angles: 0,30,45,60,90,...,330.

  Type 12 — make_inequality_graph(ax, inequalities, title='')
    2D inequality / system. Overlap shown in mediumpurple.
    inequalities: list of dicts with 'expr', 'deriv', 'color',
    'shade' ('above'|'below'), 'inclusive'

  Type 13 — make_trig_graph(ax, functions, title='')
    Sine/cosine. 2 full periods. x-axis in π fractions.
    functions: list of dicts with 'type', 'a', 'b', 'c', 'd',
    'color'

  Type 14 — make_bar_chart(ax, categories, values, title='',
              colors, ylabel, xlabel)
    Categorical comparison. Landscape 4×3in.

  Type 15 — make_histogram(ax, data, bins, title='',
              color, ylabel, xlabel)
    Frequency distributions.

  Type 16 — make_scatter_plot(ax, x_data, y_data, xmin, xmax,
              ymin, ymax, color, point_size, line_of_best_fit,
              xlabel, ylabel, title='')
    Scatter plot with optional linear regression line and arrows.

  Type 17 — make_hundred_grid(shaded_cells, shaded_color,
              filename)
    10×10 grid for percent/decimal/fraction shading.

  Type 18 — make_fraction_bar(n_parts, n_shaded, shaded_color,
              label_parts, filename)
    Horizontal tape diagram. Parts labeled with LaTeX fractions.

  Type 19 — make_algebra_tiles(expression, filename)
    Portrait auto-wrapping tile layout.
    expression: dict with keys 'x2','neg_x2','x','neg_x',
    'one','neg_one','y','neg_y','xy','neg_xy','y2','neg_y2'

SAVE FUNCTION:
  save_graph(fig, filename)
  504×504px (3.5in at 144dpi).
  Number lines save at 504×180px (3.5×1.25in).

FIGURE NAMING:
  u[#]_bank_s[#]_[descriptor]_sq_v1.png
  Example: u1_bank_s2_numberline_blank_sq_v1.png

FIGURE CREATION PATTERN:
  fig, ax = plt.subplots(figsize=(3.5, 3.5))
  fig.patch.set_facecolor('white')
  make_standard_graph(ax, functions, title='')
  save_graph(fig, 'u1_bank_s1_linearplot_sq_v1.png')
  plt.close(fig)

  For number lines use figsize=(3.5, 1.25)
  For bar charts and trig use figsize=(5.0, 2.5)
  For multi-panel grids use the figsize defined in the
  function (make_2x2_grid, make_3x1_grid, etc. return fig)

GRAPH LABELS MUST USE LATEX STRINGS:
  All title=, xlabel=, ylabel=, and cell value strings passed
  to graph_tool functions must use LaTeX where math appears.
  WRONG: title='2x^2'        cell_value='3x'
  RIGHT: title=r'$2x^2$'     cell_value=r'$3x$'
  Plain text math does not render — it appears as literal
  characters in the figure. Every label, title, and cell
  value containing math must be wrapped in $...$.

FIGURES — WHEN TO USE THEM

Every item that involves a number line, coordinate plane,
inequality graph, pattern, area model, or any visual element
MUST have a graph_tool figure. No exceptions.

Common cases requiring figures:
  Any inequality on a number line → blank number line
  Any graphing task → blank coordinate plane
  Any plotted function given as evidence → Type 1 or 2
  Any comparison of two functions → Type 9 or Type 4
  Any area model task → Type 7 (rectangle model)
  Any factoring/sum-product puzzle → Type 8 (diamond)
  Absolute value / piecewise → Type 10

  Percent/fraction visual → Type 17 or 18

MISMATCH ITEMS — TWO TYPES, DIFFERENT REQUIREMENTS:

  Type A — Expression vs table of values:
    Use an HTML table.values. The mismatch is a wrong
    computed value in one cell.
    Example: "$2x+5$ and the table are supposed to match.
    Find the first mismatch."
    | $x$    | 0 | 1 | 2  | 3  |
    | $2x+5$ | 5 | 7 | 8  | 11 |   ← x=2 should be 9
    This is correct HTML table use. Build the table carefully.

  Type B — Expression vs area model:
    Use make_rectangle_model (Type 7) — NOT an HTML table.
    An HTML table cannot show spatial area-model structure.
    The mismatch goes inside the figure (one cell value wrong).
    The expression to compare goes in the question text.
    Example structure:
      Question: "The area model and expression are meant
      to represent the same product. Find the mismatch."
      Figure: make_rectangle_model with one wrong cell value

QUESTION QUALITY RULES

RULE 1 — 10-second test
  If a strong student can answer by scanning in under 10
  seconds without computing or reasoning → it is DOK 1
  regardless of label. Apply to every DOK 2+ item.

RULE 2 — DOK level must match cognitive demand
  DOK 1: recall, recognition, single-step retrieval
  DOK 2: apply a procedure, connect representations,
          solve a routine problem
  DOK 3: construct reasoning, critique with evidence,
          justify, analyze structure across representations
  DOK 4: design, create, synthesize, model an unfamiliar
          situation, make and justify a recommendation
          5-10 min max — no projects, no multi-day

RULE 3 — DOK 3 variety (enforced by PLANNING AUDIT + Pass 5)
  Rotate across items and sections. Hard limits:
    No format more than THREE TIMES across the full bank.
    No format repeated within the same section.
    No DOK 3 block uses only one format type.
    At least one item per block requires written justification
    without a pre-categorizing table scaffold.

RULE 4 — DOK 4 variety (enforced by PLANNING AUDIT + Pass 6)
  No two sections share the same type combination.
  (design + recommend) pair at most ONCE total.
  At least two sections must use a primary type other than
  design or recommend.

RULE 4b — DOK 4 items must be usable tasks, not templates
  Do not stop at the DOK 4 type heading plus generic constraint
  bullets. Every DOK 4 item must include a concrete student-facing
  mathematical task: specific data, equation, graph/table, context,
  student approaches, flawed model, or representation to build from.
  Quick check: remove the repeated boilerplate and performance note.
  If no exact mathematical work remains, the item is a 5o violation.
  Also apply this same concrete-work check to DOK 2 and DOK 3:
  comparison, critique, method-choice, and cross-representation
  items must include the actual equation/problem, evidence, flawed
  work, approaches, or anchor representation students need.

RULE 5 — Variety within DOK blocks
  No two adjacent items same format.
  Rotate: number line / graph / table / equation / context /
  written explanation.

RULE 6 — Self-contained items. No cross-references ever.

RULE 7 — Classification requires multi-representation evidence.

RULE 8 — Mismatch structure (when used — max 2 per bank)
  Two representations with one deliberate error.
  Ask: where does mismatch first occur / how do you know /
  how should the incorrect representation be revised.

RULE 9 — Currency escaping
  All dollar amounts: \$12, \$4.50 — never bare $12.
  Scan every item. Bare $[digit] breaks MathJax on that item.

RULE 10 — No scaffolded DOK 3 (bad pattern 5k)
  Do not supply a table column that pre-labels the answer
  category (e.g., "Reasoning target: negative") before the
  student reasons. Ask for conclusion and justification
  together without handing the conclusion back.

BAD QUESTION PATTERNS — NEVER USE THESE

5a — Answer given by column labels
5b — Answer visible in graph (labeled point, guide line)
5b-graph-title — Equation or answer embedded in a graph title=
5c — Answer stated in text immediately above
5d — Cross-reference to another item
5e — Answer given in question text (answer restated)
5f — Adjacent items same task type
5g — Trivial visual sort (graph shape only)
5j — Mismatch critique with cross-reference
5k — Scaffolded DOK 3 (pre-categorizing table column)
5m — Pre-answered table (answer cells already populated)
5n — Context plausibility failure (numeric values unrealistic)
5o — Template-only / non-actionable task shell

PATTERN DEFINITIONS:

5b-graph-title — A graph title= parameter in generate_graphs.py
  contains the equation, factored form, zeros, vertex coordinates,
  or any specific value the item asks the student to produce or
  identify. This applies at ALL DOK levels — DOK 1 items are not
  exempt. If reading the graph title answers the question, the
  title must be cleared.
  ALLOWED: title='' (blank) or a generic plain-text descriptor
    such as 'Growth graph' or 'Quadratic pattern'.
  NOT ALLOWED: title=r'$f(x)=4(0.5)^x$' when the item asks
    "decide whether the multiplier is greater than 1 or between
    0 and 1"; title=r'$y=(x-1)(x-6)$' when item asks "write a
    possible factored equation"; title=r'$g(x)=2|x+1|-4$' when
    item asks "write a possible equation."
  Exception: title= may show an equation ONLY when the item
    explicitly directs students to check or verify their own
    work against a named equation that is already stated in the
    question text. The equation must appear in both places.
  Fix: change title= to title='' or a generic descriptor.
    Do not change the filename. The figure file is overwritten
    when the user re-runs generate_graphs.py.

5m — Pre-answered table: The item says "complete the table,"
  "fill in the missing values," or any equivalent phrase, but
  the answer cells that the student is supposed to fill are
  already populated in the HTML. A fully pre-filled table gives
  the student nothing to do regardless of the DOK label.
  Fix: clear the pre-populated answer cells in the HTML,
  leaving only header values, given starting values, and any
  information explicitly stated as given in the question text.

5n — Context plausibility: Numeric values in a real-world
  context item produce outputs that are implausible for the
  stated situation. Examples: a used car worth $0.05, a school
  population of 4 people growing to 200 million in a week, a
  decay factor greater than 1, a 400% annual interest rate.
  Implausible values undermine the modeling intent and confuse
  students. Fix: adjust the starting value, multiplier, or time
  unit to keep outputs in a realistic range without changing the
  mathematical structure of the item.


5o — Template-only / non-actionable task shell: The item reads
  like a template for the writer instead of a usable student
  problem. It gives a DOK type, generic topic label, broad
  constraints, repeated sentence stem, or performance note, but
  lacks the concrete equation, table, graph, context, student
  approaches, flawed model, anchor values, or representation
  students need to do the work.
  This applies at ALL DOK levels. It is common in DOK 4, but
  DOK 2 and DOK 3 items also fail when they name a comparison,
  critique, method choice, or cross-representation task without
  supplying the exact evidence or mathematical object.
  Common failures:
    — recommend between two approaches, but no equation/problem
      and no two approaches are provided;
    — revise a flawed model, but no flawed model is provided;
    — create with constraints, but only generic constraints are
      listed and no specific mathematical object is anchored;
    — design a model/context, but the prompt does not specify
      how to use the given representation or what outputs are
      required;
    — synthesize representations, but not enough information is
      provided to make all representations match one object;
    — cross-representation comparison, but one representation or
      anchor value is missing;
    — critique/error item, but the flawed claim, incorrect work,
      or mismatched evidence is missing;
    — method comparison, but the equation/problem or methods are
      not provided.
  Search method: remove the repeated boilerplate and ask what
  exact mathematical work remains. If the answer is mostly the
  teacher-facing template, the item fails.
  Fix: add the missing concrete input or required output using
  minimum change; do not rewrite the full item unless necessary.
