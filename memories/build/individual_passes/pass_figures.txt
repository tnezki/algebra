THIS FILE IS THE SINGLE SOURCE OF TRUTH FOR THE FIGURE PASS

If anything in saved memory, prior habit, or any other instruction
conflicts with this file, follow this file.

This pass is NOT a broad mandate to add visuals. It is primarily a
figure integrity and figure/prompt alignment pass.

Do not add a figure merely because a rectangle, area, graphable equation,
or visualizable context appears in the problem. A student-built model can
be intentional scaffolding. Add or require a figure only when the prompt
explicitly relies on one or would be ambiguous without it.

════════════════════════════════════════════════════════════════

WHAT THIS PASS COVERS

1. Every existing figure src= reference points to a figure generated by
   generate_graphs.py, unless the figure is intentionally supplied by a
   separate approved image source.
2. Every item that truly depends on a visual has a figure.
3. No graph title= parameter, alt text, label, or cell value reveals the
   answer students are supposed to produce.
4. Most importantly: every existing figure actually matches the prompt,
   equation, table, context, representation type, and intended reasoning.

This last point is the FIGURE/PROMPT ALIGNMENT CHECK. It catches issues
such as:
  — prompt says “graph” but the figure is an area model
  — prompt gives one equation but the graph shows a different quadratic
  — prompt asks students to compare “the graph and equation” but they do
    not represent the same function, unless the item is explicitly a
    mismatch/critique task
  — prompt asks about height over time but axes are generic or misleading
  — prompt asks students to estimate from a graph but the exact equation
    is given before the estimate step
  — a figure is attached to an item that never references or needs visual
    evidence, making the item easier or confusing

IF A FIX REQUIRES A CORRECTED TITLE on an existing figure:
  Update only the title= parameter in the existing graph call.
  Do not change the filename.

IF A FIX REQUIRES A CORRECTED GRAPH on an existing figure:
  Update the function/expression/axis labels in the existing graph call.
  Do not change the filename.
  The corrected figure will be overwritten when generate_graphs.py is rerun.

IF A FIX REQUIRES A NEW FIGURE:
  Append a new graph block below all existing appended code.
  Use a new unique filename.
  Reference the new filename in the fixed HTML item.

GRAPH LABEL RULE:
  All title=, xlabel=, ylabel=, legend label, cell_value, row label, and
  column label strings that contain math must use LaTeX.
    WRONG: title='2x^2'
    RIGHT: title=r'$2x^2$'
  Plain words such as 'Time', 'Height', 'Quadratic model', or 'Area model'
  are allowed without LaTeX.

Items that USUALLY need a figure:
  — prompt says “the graph shows,” “use the graph,” “provided graph,”
    “shown below,” “in the figure,” “area model shows,” “rectangle model
    shows,” or similar
  — student must plot, graph, mark, shade, complete, or read a visual
  — graphing inequalities or number-line solution tasks
  — area-model or algebra-tile tasks where the model is provided to read
    or complete
  — mismatch, critique, or cross-representation items that depend on a
    visual representation

Items that USUALLY do NOT need a figure:
  — pure computation, solve, simplify, factor, evaluate
  — written explanation with no visual evidence
  — context word problems that can be modeled from text alone
  — “build/draw/create an area model” tasks where the student is meant to
    create the visual representation
  — rectangle dimension contexts stated fully in words

Important distinction:
  “Complete the area model shown” needs a figure.
  “Build an area model for…” does not necessarily need a provided figure.
  “A rectangle has width ___ and length ___” does not automatically need
  a figure.

PART B — FIGURE/PROMPT ALIGNMENT CHECK

For every figure src= reference in the HTML:

1. Identify the item ID and figure filename.
2. Read the exact prompt text.
3. Find the corresponding graph block in generate_graphs.py.
4. Determine what the figure actually shows:
   — representation type: graph, area model, number line, table-like grid,
     diagram, blank coordinate plane, etc.
   — equation or function shown, if any
   — roots/intercepts/zeros
   — vertex/maximum/minimum
   — opening direction and approximate scale
   — axis labels and context labels
   — visible constants, dimensions, cell values, or labels
5. Compare the figure to the prompt.

Alignment questions to ask:

A. REPRESENTATION TYPE
  — Does the prompt call the figure a graph when it is actually an area
    model, rectangle model, algebra-tile model, or blank grid?
  — Does the prompt call it an area model when it is actually a coordinate
    graph?
  — Does the prompt say “provided graph” when the figure does not show a
    graph?

B. EQUATION / FUNCTION MATCH
  — If the prompt gives an equation and says to use the graph, does the
    graph show that exact equation?
  — If the prompt asks whether the graph and equation represent the same
    quadratic, is it supposed to be a match or a mismatch?
  — If it is not explicitly a mismatch/critique item, assume the graph and
    equation should match.

C. FEATURE MATCH
  — Do the graph’s zeros/intercepts match the prompt’s zeros, solutions,
    or factored form?
  — Does the vertex match the vertex form or stated maximum/minimum?
  — Does the graph open in the direction described by the prompt?
  — Do the graph scale and window allow students to see the needed features?

D. CONTEXT MATCH
  — If the prompt says height over time, revenue vs price, area vs width,
    distance vs time, etc., do the axes support that context?
  — Generic x/y labels are acceptable for abstract algebra but should be
    flagged as a discussion point for explicit modeling contexts.
  — If a prompt asks students to interpret time, height, price, area, or
    other quantities, check whether the visual helps rather than confuses.

E. TASK SEQUENCE / OVER-SCAFFOLDING
  — If the prompt says “estimate from the graph,” does the graph title,
    alt text, or first sentence give the exact equation or answer first?
  — If the prompt asks students to write an equation from a graph, does the
    figure title give the equation away?
  — If the visual makes a DOK 3 or DOK 4 item a 10-second read-off task,
    flag it as a recommendation rather than automatically changing it.

F. UNREFERENCED OR STRAY FIGURES
  — If a figure is attached but the prompt never references it and does not
    need visual evidence, flag it.
  — Recommend either removing the figure reference or revising the prompt
    so the figure is meaningfully used.

Output for every figure:
  [filename] used by [ID]
    Figure type: [graph/area model/etc.]
    Prompt expects: [graph/area model/etc.]
    Equation/features shown: [brief]
    Prompt equation/features: [brief]
    Alignment: OK / VIOLATION / DISCUSS
    Recommendation: [fix or none]

PART C — GRAPH TITLE AND ALT-TEXT LEAK CHECK

For every figure src= reference in the HTML, find its corresponding graph
call in generate_graphs.py and examine title=.
Also examine the image alt= text in HTML.

THE RULE:
  A graph title or alt text MUST NOT contain the equation, formula,
  factored form, zeros, vertex coordinates, multiplier, maximum, minimum,
  or other specific value that the item asks students to produce, identify,
  estimate, or find.

Allowed titles:
  title=''
  title='Quadratic model'
  title='Scatter plot'
  title='Height over time'
  title='Area model'

Allowed alt text:
  alt="supporting graph for [ID]"
  alt="blank coordinate plane"
  alt="partial area model for [ID]"
  alt="quadratic graph for comparison task"

Not allowed unless already given in the prompt:
  title=r'$y=(x-1)(x-6)$'
  alt="graph of y=(x-1)(x-6) with zeros 1 and 6"
  title=r'$h(t)=-4(t-5)^2+60$'
  alt="graph with maximum at (5,60)"

Exception:
  A title or alt text may include an equation only when the item explicitly
  directs students to check or verify against that same named equation and
  the equation already appears in the prompt text.

Graph title / alt-text output:
  [filename]: title=[value] — OK/VIOLATION
  [ID]: alt=[value] — OK/VIOLATION
