WHAT THIS PASS COVERS

Pass 4 from the full bank quality system. This is the
workhorse pass — it is the most judgment-intensive check
and catches the defects most likely to harm students.

Two primary checks:
  A. The 10-second test — applied to every DOK 2+ item.
  B. Bad patterns 5a–5o — applied to every item at every
     DOK level.

Both checks must reach PASS before assembling the ZIP.

CHECK A — 10-SECOND TEST (DOK 2+ items only)

For every item labeled DOK 2, DOK 3, or DOK 4:

  Ask: If a strong student read this item and scanned the
  figure, table, or choices provided — could they produce
  a plausible answer in under 10 seconds without computing
  or reasoning?

  If YES → the item has DOK 1 cognitive demand regardless
  of its label. It must be revised or relabeled.

  The test is about cognitive demand, not time. An item
  that requires a genuine procedure, comparison, or
  inference passes even if a fast student completes it
  quickly. An item that requires only reading a visible
  answer — from a title, label, or column header — fails.

List every failure:
  [ID]: [brief description of why it fails the 10-second test]

CHECK B — BAD PATTERN AUDIT (all items, all DOK levels)

Check every item against every pattern below.
DOK 1 items are NOT exempt from pattern checks 5b, 5b-graph-title,
5m, 5n, and 5o — those apply regardless of DOK level.

────────────────────────────────────────────────────────────────
5a — ANSWER GIVEN BY COLUMN LABELS

A table column header already states what the student is
supposed to determine. Example: the header says "Growth or
Decay?" and the student fills in the obvious word.
Fix: remove the answer-revealing column and restructure the
ask so the student must state and justify their conclusion.

────────────────────────────────────────────────────────────────
5b — ANSWER VISIBLE IN GRAPH (labeled point, guide line)

A plotted figure includes a labeled point, labeled intersection,
or guide line that directly reveals the answer the student is
asked to find (e.g., "find the x-intercept" but the graph has
the intercept labeled as a coordinate pair).
Fix: regenerate the figure without the revealing label.
Append a corrected graph block to generate_graphs.py.

────────────────────────────────────────────────────────────────
5b-graph-title — EQUATION OR ANSWER IN GRAPH TITLE

A graph title= parameter in generate_graphs.py contains the
equation, factored form, zeros, vertex, multiplier, or any
specific value that the item asks the student to produce
or identify.

APPLIES AT ALL DOK LEVELS — DOK 1 is not exempt.

HOW TO CHECK: For every figure src= in the HTML, find its
  graph call in generate_graphs.py. Read the title=. Then
  read the item question. If the title answers the question
  or reveals what the student is asked to find → VIOLATION.

EXAMPLES OF VIOLATIONS:
  Item asks: "estimate the y-intercept"
    title=r'$f(x)=3(2)^x$' → VIOLATION (y-int = 3, visible)
  Item asks: "write a possible factored equation"
    title=r'$y=(x-1)(x-6)$' → VIOLATION (is the answer)
  Item asks: "decide whether multiplier > 1 or 0 < b < 1"
    title=r'$f(x)=4(0.5)^x$' → VIOLATION (0.5 is in title)
  Item asks: "use the graph to estimate the equation"
    title=r'$f(x)=2(1.5)^x$' → VIOLATION (is the answer)
  Item asks: "write a possible equation for the transformation"
    title=r'$g(x)=2|x+1|-4$' → VIOLATION (is the answer)

ALLOWED: title='' (blank) or plain-text generic descriptor
  Examples: 'Growth graph', 'Decay pattern', 'Quadratic model'

EXCEPTION: title may show an equation ONLY when the item
  explicitly directs students to verify their work against
  a named equation already stated in the question text.
  The equation must appear in both the title and the question.

FIX: In generate_graphs.py, change the title= parameter to
  title='' or a generic descriptor. Do not change the filename.
  The figure overwrites on re-run. Flag in QA LOG.

────────────────────────────────────────────────────────────────
5c — ANSWER ENCODED IN QUESTION TEXT OR NOTATION

The question text itself restates the answer through notation
or phrasing. Example: "Show that the factored form is
(x+3)(x-5) by..." — the factored form is already given.
Fix: remove the embedded answer and ask for the finding
and justification separately.

────────────────────────────────────────────────────────────────
5d — CROSS-REFERENCE TO ANOTHER ITEM

The item says "use your answer from part (b)" or "from the
previous question" or references another item by number.
No item may depend on another item for its inputs.
Fix: make the item self-contained, providing any needed
context directly in the question text.

────────────────────────────────────────────────────────────────
5e — ANSWER RESTATED IN QUESTION

The question gives the answer and asks the student to confirm
or label it. Example: "The answer is 12. Explain why."
Fix: ask for the finding and justification without stating
the answer first.

────────────────────────────────────────────────────────────────
5f — ADJACENT ITEMS SAME FORMAT

Two consecutive items in the same DOK block use identical
question formats (e.g., two back-to-back "complete the table"
items, two consecutive "evaluate the expression" items).
Fix: reorder items or change one to a different format.

────────────────────────────────────────────────────────────────
5g — TRIVIAL VISUAL SORT (graph shape only)

An item asks "does this graph show growth or decay" and the
answer is immediately obvious from the direction of the curve,
with no computation or threshold reasoning needed.
Fix: add a multiplier or rate question that requires checking
rather than just reading the direction.

────────────────────────────────────────────────────────────────
5j — MISMATCH CRITIQUE WITH CROSS-REFERENCE

A mismatch item references another problem or asks the student
to compare against an answer they produced in a prior item.
Fix: embed all needed information directly in the item.

────────────────────────────────────────────────────────────────
5k — SCAFFOLDED DOK 3 (pre-categorizing table column)

A DOK 3 item supplies a table with a column that pre-labels
the answer category before the student reasons. Example: a
table column labeled "Reasoning target: Growth or Decay?"
hands the student the framework for their answer.
Fix: remove the pre-categorizing column. Ask for the
conclusion and justification without the scaffold.

────────────────────────────────────────────────────────────────
5m — PRE-ANSWERED TABLE

The item says "complete the table," "fill in the missing
values," "find and record," or any equivalent phrase — but
the cells the student is supposed to fill are already
populated in the HTML.

HOW TO CHECK: Read the item question. If it asks the student
  to fill in values, count the blank cells in the table.
  If there are fewer blank cells than expected outputs, or
  if all answer cells are already filled → VIOLATION.

APPLIES AT ALL DOK LEVELS.

EXAMPLES:
  Item says: "Complete the coefficient-and-variable-power
  table for 18x³ − 12x² + 6x" but the HTML table already
  shows Coefficient: 18, −12, 6 and Power of x: 3, 2, 1.
  → VIOLATION: student has nothing to do.

FIX: In the HTML, clear the pre-populated answer cells.
  Leave only header values and any values explicitly stated
  as given in the question text. The student's work cells
  should render as empty <td></td> cells.
  Smallest fix: remove text content from answer cells only.

────────────────────────────────────────────────────────────────
5n — CONTEXT PLAUSIBILITY FAILURE

A real-world context item uses numeric values that produce
outputs implausible for the stated situation.

EXAMPLES OF VIOLATIONS:
  A used car valued at $0.08 after depreciation.
  A school of 4 students growing to 80 million in 6 days.
  A "5% decay" where the multiplier is written as 1.05.
  An investment account with a 400% annual interest rate.
  A medication dose of 500 mg with a "15% elimination"
  that leaves 75,000 mg after one hour.

Implausible values are not merely aesthetically off —
they actively confuse students trying to build intuition
about exponential models.

FIX: Adjust the starting value, multiplier, or time unit
  to keep the context outputs in a realistic range.
  Do not change the mathematical structure of the item
  (same skill, same DOK level, different numbers).
  If the item is number-swappable, the fix is minimal —
  just swap the numbers to something realistic.

────────────────────────────────────────────────────────────────
5o — TEMPLATE-ONLY / NON-ACTIONABLE TASK SHELL

The item reads like directions for writing a task rather than
an actual student-facing task. It gives a DOK type, a generic
skill label, broad constraints, or a performance note, but it
omits the concrete mathematical input students need to work.

This applies at ALL DOK levels. It is especially common in
DOK 4 items, but DOK 2 and DOK 3 items can also fail when they
name a task structure without supplying the actual evidence or
mathematical object students must use.

HOW TO CHECK:
  Strip away reusable boilerplate such as the DOK type heading,
  topic name, generic constraint bullets, repeated sentence stem,
  and performance notes. Then ask: what exact mathematical work
  can a student do from what remains?

FLAG AS A VIOLATION IF:
  — A "recommend between two approaches" item does not provide
    the equation/problem and the two approaches to compare.
  — A "revise a flawed model" item does not provide the flawed
    model and the target situation or requirements for revision.
  — A "create with constraints" item gives only generic
    constraints, with no specific quantities, representations,
    or concrete conditions to satisfy.
  — A "design a model or context" item includes a figure or
    broad direction but does not specify how students should use
    it or what final mathematical products are required.
  — A "synthesize representations" item asks for multiple
    representations but does not provide enough information to
    anchor one shared mathematical object.
  — A cross-representation comparison says to compare an equation,
    table, graph, context, or model but one of the needed
    representations or anchor values is missing.
  — A critique/error item asks students to locate or revise an
    error but does not provide the incorrect work, flawed claim,
    mismatched representation, or enough evidence to critique.
  — A method-comparison item asks which method is better but does
    not provide the equation/problem or the methods being compared.

A valid item can be open-ended, but it must still be a usable
student question. Students should be able to start from the
specific evidence or constraints in the card, not from the
teacher's intent behind the card.

FIX: Use minimum change. Keep the item type and DOK label if
  possible, but add the missing concrete input: equation,
  graph/table directions, context values, two approaches,
  flawed model, required outputs, anchor values, or specific
  constraints. Do not rewrite the whole item if one sentence or
  one missing representation makes it usable.

GENERATE_GRAPHS.PY — TITLE FIX RULES

When fixing a 5b-graph-title violation:
  1. In generate_graphs.py, locate the graph call for the
     figure referenced by the item.
  2. Change ONLY the title= parameter: to title='' or a
     plain-text generic descriptor.
  3. Do NOT change the filename, function arguments,
     color, data values, or any other parameter.
  4. Do NOT modify any line above the append marker.
  5. The figure will be overwritten on re-run — this is
     the correct behavior.

When a single figure is used by multiple items:
  Evaluate ALL items using that graph. If any item has a
  title violation, clear the title. The other items using
  that graph will not be harmed by a blank title.

DELIVERY

After Pass 4 reaches PASS, assemble the ZIP.

ZIP structure for a ready-to-open package:
  unit[#]/
    unit[#].html          ← corrected HTML with updated QA LOG
    figures/              ← generated PNG files for every HTML img src
    generate_graphs.py    ← original code + any title= fixes

Default delivery is a ready-to-open package. Do NOT deliver
HTML that references missing images. If the HTML contains
<img src="figures/..."> references, those PNG files must be
present in the zipped figures folder unless the user explicitly
asks for a source-only package.

Source-only exception:
  Only when the user explicitly asks for source files only,
  the figures folder may be empty. In that case the ZIP filename
  must include source_only, and the final response must clearly
  say that figures are not included and the user must run
  generate_graphs.py before opening the HTML.

Update the QA LOG embedded comment at the top of the HTML
to reflect the current pass results before zipping.

Always deliver a ZIP. Never deliver HTML-only.
Always include generate_graphs.py — even when generated figures
are included — so future figure changes can be reproduced.

FIGURE DELIVERY CHECK — MANDATORY BEFORE ZIPPING

If the HTML contains any <img src="figures/..."> references:

  1. Run generate_graphs.py after all HTML and graph-code fixes.
     This is required even if only title= values changed, because
     the PNGs must reflect the corrected graph code.

  2. Parse the corrected HTML and collect every figure path from
     <img src="figures/...">.

  3. Verify each referenced file exists at that exact relative path
     inside the unit folder and has nonzero file size.

  4. Verify every referenced file is included in the ZIP under the
     same relative path used by the HTML.

  5. If any referenced image is missing, zero bytes, stored under
     the wrong folder, or excluded from the ZIP, FAIL DELIVERY.
     Regenerate/copy the figures and rebuild the ZIP before
     responding.

  6. Do not describe broken image links as a naming problem unless
     the path truly differs. First check for missing generated PNGs.
