CSS LINK RULE

The section HTML must link to the external shared CSS with exactly:

  <link rel="stylesheet" href="../css/styles.css">

The HTML must never link to:

  css/styles.css
  ./css/styles.css
  ../../css/styles.css
  cp_section_[chapter]_[section]/css/styles.css

Do not create a <style> block.
Do not inline CSS.
Do not write or copy styles.css.
Do not put CSS into README.txt as a substitute.

The required class names below are already supported by the external shared stylesheet.
Use these class names consistently so the existing CSS can style the page.

================================================================
HTML STRUCTURE BASELINE

Use semantic HTML. Keep the layout simple and consistent.

Use this general structure for section pages:

<!DOCTYPE html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1.0">
<title>Conceptual Physics - Section [#.#]: [Section Title]</title>
<link rel="stylesheet" href="../css/styles.css">
</head>
<body>
<header class="site-header">
  <p class="kicker">Conceptual Physics</p>
  <h1>Chapter [#]: [Chapter Title]</h1>
  <h2>Section [#.#]: [Section Title]</h2>
</header>
<main class="wrapper">
  <article class="main-body">
    <!-- section content goes here -->
  </article>
</main>
</body>
</html>

Chapter title pages can be simple. If the requested task is only a chapter title page, make a simple page that says the chapter title and has the same shared CSS link.

Do not include MathJax unless the section genuinely needs it. If MathJax is needed, add it in the head before the CSS link, but keep the CSS link exactly ../css/styles.css.

CONTENT CLASSES TO USE

Use these classes for content types:

  <article class="main-body">

regular section heading:
  <h3>...</h3>

figures:
  <figure class="figure"> ... </figure>

  <span class="figure-label">Figure #.#</span>

margin notes or margin text:
  <aside class="margin-note">...</aside>

FYI or FYI-style content:
  <aside class="fyi">...</aside>

blue textbook boxes:
  <aside class="blue-box">...</aside>

checkpoints:
  <aside class="checkpoint">...</aside>

checkpoint answers:
  <aside class="check-answer">...</aside>

personal essays:
  <section class="personal-essay">...</section>

Practicing Physics:
  <section class="practicing-physics">...</section>

Hang Time or similar enrichment:
  <section class="hang-time">...</section>

summary or review questions:
  <section class="summary-box">...</section>

media links, QR/video notes, interactive notes:
  <aside class="media-link">...</aside>

footnotes:
  <section class="footnotes">...</section>
  <div class="footnote">...</div>

omitted figure note:
  <p class="omitted-figure">Figure #.# was omitted because no matching captured image was supplied.</p>

source note:
  <p class="source-note">...</p>

TEXT EXTRACTION RULES

Copy section prose verbatim from the textbook PDF.
Keep the textbook's section order.
Preserve short paragraphs as separate paragraphs when possible.
Remove page headers, footers, page numbers, repeated part/chapter labels, and isolated artifacts that are not part of the section content.
Preserve bold/italic emphasis when it is obvious and useful.
Do not insert new explanations into the body.
If you need to explain a source problem, put it in README.txt or a source-note, not inside the textbook prose.

Margin content belongs in the main flow near the paragraph or figure it supports.
Do not try to position it in the visual margin.
Use margin-note, fyi, blue-box, checkpoint, or other classes as appropriate.

If the PDF extraction has broken words or line breaks, clean only obvious extraction artifacts. Do not rewrite wording.

If the uploaded/trimmed source ends mid-sentence or appears to omit pages on purpose:
- Stop where the source stops.
- Do not invent missing continuation.
- Add a clear note in README.txt.
- Add a short final-response note reminding the user to double-check the intentional omission.

FIGURE AND IMAGE RULES

Use only the captured image archive supplied by the user.
Do not extract embedded images from the PDF unless the user explicitly asks.
Do not generate missing figures.
Do not redraw figures.
Do not use placeholder art.
Do not use online images.
Do not crop new figures from screenshots unless the user explicitly asks.

For each included figure:
- Copy the matching captured image into cp_section_[chapter]_[section]/images/.
- Use a relative image path such as images/filename.png.
- Put the textbook figure description below the image as the figcaption.
- Begin each caption with Figure #.#.

Caption pattern:

<figure class="figure">
  <img src="images/[filename].png" alt="Figure #.#: [short accessible description]">
  <figcaption><span class="figure-label">Figure #.#</span> [verbatim textbook caption or description]</figcaption>
</figure>

If a textbook figure is referenced in the section but no matching captured image is supplied:
- Leave the image out.
- Optionally add an omitted-figure note if it helps the user track the omission.
- Record the omission in README.txt.

If the captured image filename is already in the locked curriculum naming format, preserve that filename.
If it is not, use a clean filename inside the section images folder:
  figure_[chapter]_[figure]_[short_description].png
or for unnumbered practice/review images:
  figure_[chapter]_pp_[short_description].png

Do not rename a supplied image silently if that would break traceability; record original filename to final filename in image_manifest.csv.

2. Including any css/ folder in the section ZIP.
3. Creating a nested folder like cp_section_2_3/cp_section_2_3/index.html.
4. Linking CSS as css/styles.css instead of ../css/styles.css.
5. Using the word prototype in file/folder names.
6. Generating or recreating missing images.
7. Pulling images from the PDF instead of using supplied captured images.
8. Omitting margin content, FYI boxes, blue boxes, checkpoints, essays, or summaries that belong to the section.
9. Trying to visually place margin notes in the margin instead of using a class in the main flow.
10. Summarizing or rewriting textbook prose during extraction.
11. Forgetting figure captions or not starting them with Figure #.#.
12. Not recording omitted figures.
13. Not flagging mid-sentence endings or intentional PDF omissions.
14. Missing README.txt, source files, or image_manifest.csv.
15. Delivering a ZIP whose root contains both css/ and cp_section_x_y/.
16. Delivering a ZIP whose root contains only loose index.html/images/source instead of cp_section_x_y/.
17. Reporting pass/fail without checking the actual ZIP listing.
