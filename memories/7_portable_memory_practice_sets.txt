PRACTICE SETS SHEET — how to read it

The Practice Sets sheet has:
  Row 1:  Column headers:
            Col A: "Section / Slot"
            Col B: PS1 — Practice Set 1
            Col C: PS2 — Activity 1
            Col D: PS3 — Activity 2
            Col E: PS4 — Extra Practice

    Row [N]:      "Section [X].[Y]" header (no data in cols B–E)
    Rows [N+1–4]: Slots 1–4 (current)  ← bank IDs
    Rows [N+5–12]:Slots 5–12 (mastery) ← bank IDs
    Rows [N+13–16]:Slots 13–16 (last)  ← bank IDs
    Row [N+17]:   EXIT TICKET / CYU note

To find the requested section:
  1. Scan col A for "Section [X].[Y]" matching the build request.
  2. Read rows N+1 through N+16 in the requested PS column (B, C, D, or E).
  3. The 16 bank IDs are the complete content for that PS.

PROBLEM ORDERING in each PS:
  Slots 1–4:   current section items (label: Current)
  Slots 5–12:  mastery spiral items (label: Mastery Spiral)
  Slots 13–16: last section spiral items (label: Last Section Spiral)

BANK HTML — how to extract item content

Multiple bank files may be needed. Use the file whose prefix matches the ID:
  U[N]- prefix → unit[N].html  (current unit bank)
  0A- prefix   → unit0A.html   (prior unit bank)
  0B- prefix   → unit0B.html   (prior unit bank)
Search within the correct file for each item.

Bank item structure:

Extract rules:

If a bank ID is not found in the bank HTML:

CYU ITEM SELECTION — from PS4 bank IDs

The CYU picks 6 items from the PS4 column's 16 bank IDs:
  • 2 from current (slots 1–4): pick the two that best represent
    DOK 1–2 and have different question formats.
  • 2 from last (slots 13–16): pick the two most accessible (DOK 1–2).
  • 2 from mastery (slots 5–12): pick one DOK 1–2 and one DOK 2–3.

Selection criteria:
  • Prefer different question formats (computation vs. interpretation,
    table vs. equation, etc.).
  • Prefer the most instructionally clear and self-contained items.
  • Do NOT always pick the first two IDs. Choose deliberately.

Exit tickets are not pulled from the bank. Write 4 short questions:
  ET Q1: current section skill, DOK 1–2, one format
  ET Q2: current section skill, DOK 1–2, different format from Q1
  ET Q3: previous section skill, DOK 1–2
  ET Q4: mastery/prerequisite skill from a prior unit, DOK 1–2

Exit ticket questions must be short (answerable in the cell space without workspace).

MATCHING PROBLEMS — mandatory scramble rule

When a bank item (or AI-derived question) asks students to match items
(graphs to equations, tables to equations, contexts to representations):
  ✗  Correct: Graph A→Eq 1, Graph B→Eq 2, Graph C→Eq 3, Graph D→Eq 4
     Items listed in the same order as correct answers → trivially solved by position.
  ✓  Shuffle at least one side so that answer N ≠ position N.
     Students must engage with the math, not just copy position numbers.

For bank items that arrive with matching content already structured:
  Check whether the correct matches fall in position order.
  If yes, reorder the equation/option list (not the graphs/tables) to break the pattern.
  Note the reorder in the problem-meta comment.

PROBLEM RULES

Content:
  • Copy bank item body verbatim. Never paraphrase or simplify.
  • If the item has a blank table or blank graph, copy it — it is the workspace.
  • If the item references a figure that is NOT blank (a specific graph),
    recreate it using graph_tool.py.

Format:
  • problem-title: problem number + problem-meta (DOK level, category, source ID)
  • problem-body: item content + workspace div (sized by DOK level)
  • All problems flow in sequence — no .ps-page wrappers, no break-after
  • ALL text content inside problem-body MUST be wrapped in <p> tags.
    Bare text nodes directly in a flex column break MathJax rendering —
    each math expression becomes its own line instead of flowing inline.
    ✗  <div class="problem-body">Write a rule for $f(x)=2x+1$.</div>
    ✓  <div class="problem-body"><p>Write a rule for $f(x)=2x+1$.</p></div>
    This applies to exit ticket cells and CYU problems too.

Workspace sizing guide:
  wu-ws-150: DOK 1 (identify, read, name)
  wu-ws-250: DOK 2 (construct, apply, complete)
  wu-ws-300: DOK 3 (critique, justify, compare)
  wu-ws-350: DOK 4 (design, synthesize)
  wu-ws-000: problem provides a table/graph for student work

────────────────────────────────────────────────────────────────

GRAPH TOOL RULES

Use graph_tool.py for ALL figures. No exceptions.
Read every function signature before writing any call.
Never guess argument order.

generate_graphs.py structure:
  Top = full graph_tool.py source (copy verbatim, never modify)
  Bottom = graph generation blocks only, appended after the marker:
    # PASTE YOUR GRAPH CODE BELOW THIS LINE
  No imports, OUTPUT_DIR, os.makedirs, or matplotlib.use() in appended blocks.

INDENTATION RULE — most common graph script failure:
  Every appended graph call MUST start at column 0 (zero leading spaces or tabs).
  ✗  Wrong — causes IndentationError:
       make_rectangle_model(...)        ← leading spaces = crash
  ✓  Correct:
     make_rectangle_model(...)          ← starts at column 0
  Multi-line calls: continuation lines indent normally relative to the opening call,
  but the first line of every top-level call must be at column 0.

Figures folder is always EMPTY in the delivered ZIP.
Graph title= must never contain the answer. Use title='' or neutral label.

Naming for practice set figures:
  u[unit]_ps_s[section]_[descriptor]_sq_v1.png
  Example: u1_ps_s2_relation_points_sq_v1.png

If no items reference figures: omit generate_graphs.py and figures/ entirely.

If a required graph type is not in graph_tool.py:
  ══ STOP ══  State exactly which type is missing. Wait.

────────────────────────────────────────────────────────────────

MATHJAX RULES

  window.MathJax config MUST come before the CDN script.
  processEscapes: true — always include.
  CDN: cdn.jsdelivr.net only.
  Delimiters: $...$ inline, $$...$$ display. Never \(...\) or \[...\].

  Currency — $[digit] in prose is NEVER a math delimiter:
    ✗  "The cost is $5."   ← MathJax hunts for a closing $ and breaks
    ✓  "The cost is \$5."
    ✓  "The cost is 5 dollars."
    Rule: every dollar-sign amount in prose uses \$N, not $N.

  Fractions — always \frac{a}{b}, never a truncated form:
    ✗  \rac{6}{2x-3}   ← missing the f; MathJax cannot render this
    ✓  \frac{6}{2x-3}
    After writing any fraction, scan: if \rac appears, it is corrupted. Fix it.

  Math comparisons: \lt and \gt not < and >.
