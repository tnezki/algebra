================================================================
MATHJAX — HARD REQUIREMENT
================================================================

Use MathJax for ALL symbolic algebra notation.

Approved MathJax v3 pattern:

  <script>
    window.MathJax = {
      tex: {
        inlineMath: [['$', '$']],
        displayMath: [['$$', '$$']],
        processEscapes: true
      }
    };
  </script>
  <script defer src="https://cdn.jsdelivr.net/npm/mathjax@3/es5/tex-mml-chtml.js"></script>

Use:
  • $...$ for inline math
  • $$...$$ for display math

Examples:
  $3x+5=17$
  $y=mx+b$
  $x^2+5x+6=(x+2)(x+3)$
  $\frac{a}{b}\div\frac{c}{d}=\frac{a}{b}\cdot\frac{d}{c}$

IMPORTANT — ESCAPING RULE:
HTML source must contain ONE backslash before a TeX command.

CORRECT:
  $\frac{a}{b}$

INCORRECT IN HTML SOURCE:
  $\\frac{a}{b}$

The doubled version can render as literal words such as "frac", "text", or "Rightarrow".

COMPARISON SYMBOL RULE:
Do not place raw < or > inside MathJax text in HTML.
Use:
  \lt
  \gt
  \le
  \ge

Example:
  $a\lt b \Rightarrow -a\gt -b$

Do not rely on raw browser entities inside math when a TeX command is available.

SPACING:
Use TeX spacing commands such as:
  \qquad
  \quad
  \,
Do not insert literal tab characters inside math.

================================================================
MATHJAX FIXER / AUDIT — QA SAFETY NET
================================================================

The upgraded MathJax fixer should be used as a FINAL QA safety net, not as a substitute for
writing correct source HTML.

The approved upgraded fixer handles, within math blocks:
  • doubled TeX command slashes such as \\frac -> \frac
  • raw < / > normalization to \lt / \gt
  • &lt; / &gt; normalization inside math
  • serialized comparison corruption caused by browser HTML parsing
  • literal tabs inside math -> TeX spacing
  • legacy control-character corruptions
  • legacy \(...\) / \[...\] delimiter conversion
  • MathJax CDN/config audit
  • currency audit without false positives on normal algebra expressions

Recommended QA workflow:
  1. Build all HTML.
  2. Run the fixer/audit on the build folder.
  3. Inspect any listed fixes/warnings.
  4. Run it a SECOND time.
  5. Second pass should report:
       0 files auto-fixed
       0 audit warnings

If second pass still changes files, do not deliver yet.

================================================================
UNIT AT A GLANCE
================================================================

Purpose:
  • give students the conceptual story of the unit before details
  • show how the major algebra ideas connect
  • communicate the unit-level learning arc

Good content:
  • concise introductory paragraph
  • concept chain / flow
  • one unit-level target/standard card when useful

Do not turn this into a long chapter summary.

================================================================
UNIT-WIDE VOCABULARY
================================================================

Include important vocabulary students are expected to recognize/use across the unit.

Preferred design:
  • grouped vocabulary cards/chips
  • groups may follow sections or conceptual families
  • list terms, not paragraphs of definitions, unless the user asks for definitions

Section-specific vocabulary may be repeated later in a smaller "Key terms" strip.
The full bank should appear once near the top so students can scan the unit quickly.

Only include terms supported by the assessment plan/notes/current assessments.

================================================================
RULES / FORMS / RELATIONSHIPS BLOCK
================================================================

Include every important symbolic rule, algebraic form, property, or structural relationship
students are expected to use in the unit.

For each card, prefer:
  • short name/label
  • MathJax expression or structural pattern
  • one concise explanation of what it means / when it applies

Examples of valid cards when source-supported:
  • Fraction division
  • Order of operations
  • Distributive property
  • Combine like terms
  • Equation balance
  • Inequality sign reversal
  • Slope formula
  • Point-slope form
  • Exponent product rule
  • Difference of squares
  • Quadratic formula

HARD RULE:
State CONDITIONS / LIMITATIONS when a method has one.
Examples:
  • like terms combine only when variable/exponent parts match
  • inequality direction reverses only when multiplying/dividing by a negative
  • square-root method may produce ± solutions when solving x² = k
  • factoring methods depend on the expression structure
  • graph transformations should be described relative to the taught parent function

Do not add unsupported rules merely because they are common Algebra rules.

================================================================
BULLETED SUMMARY STANDARD
================================================================

Summaries should be:
  • bulleted
  • concise
  • source-grounded
  • written for student review, not teacher commentary
  • focused on procedures, structures, representations, distinctions, and reasoning

Avoid giant prose blocks.
Avoid copying notes word-for-word.
Avoid motivational filler.

================================================================
DOK INSIDE THE REVIEW
================================================================

The review page may show compact DOK cards inside each section and a larger unit-wide DOK
map near the end.

Purpose:
  • tell students what increasing depth of thinking looks like in THIS algebra content
  • distinguish recall from application and strategic reasoning
  • NOT reorganize the entire unit away from its section sequence

Typical Algebra progression:
  • DOK 1 — Identify / recall / evaluate straightforwardly / name a property
  • DOK 2 — Apply / solve / graph / compare / interpret / convert representations
  • DOK 3 — Justify / diagnose an error / connect representations / critique strategy /
            explain why a method works / choose among methods
  • DOK 4 — Extended modeling / design / synthesize / investigate WHEN source-supported

HARD RULE:
Do not invent unsupported DOK expectations merely to fill four boxes.
If DOK 4 is not a normal assessed expectation, either omit it or clearly label it as an
extension/challenge.

Unit 0A prototype interpretation:
  • DOK 4 in a section may be shown as an extension when the assessment plan does not treat
    it as a normal required level.

================================================================
COMMON ERRORS / MISCONCEPTIONS
================================================================

Include concise error cards when supported by notes/assessments.

Good Algebra examples:
  • distributing to only the first term
  • combining unlike terms
  • losing a negative sign
  • treating division by a fraction incorrectly
  • doing addition before multiplication because of left-to-right confusion
  • not performing the same operation on both sides of an equation
  • forgetting to reverse an inequality after multiplying/dividing by a negative
  • reading slope as x-change over y-change
  • confusing x- and y-intercepts
  • treating function notation as multiplication
  • mixing exponent rules
  • factoring when the structure does not support the chosen pattern
  • forgetting ± where appropriate
  • interpreting a graph outside its domain/context

These are STUDY-GUIDE warnings, so they may explicitly state the correct idea.
They are not assessment questions.

PRACTICE-PAGE VISUAL SAFETY
================================================================

Unlike the main review, a figure used as part of a student practice QUESTION must not reveal

PRACTICE QUESTION COUNT / BALANCE
================================================================

DEFAULT FOR A NORMAL FIVE-SECTION ALGEBRA UNIT:
  20 open-response questions total.

Approved default allocation:
  • 4 questions per section

The approved batch design used a private cognitive balance of:
  • 1 DOK 1 per section
  • 2 DOK 2 per section
  • 1 DOK 3 per section

For a five-section unit, that produces:
  • 5 DOK 1
  • 10 DOK 2
  • 5 DOK 3
  • 20 total

These DOK labels are PRIVATE DESIGN METADATA and are NOT displayed to students.

This is a strong default, but alignment matters more than a rigid quota.
If a section genuinely does not support the pattern, adjust privately while preserving
quality and source alignment.

No routine DOK 4 on the student review practice page unless the user explicitly asks for
extended synthesis/challenge practice.
