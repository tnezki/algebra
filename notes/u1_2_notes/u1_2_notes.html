I can formulate a rule that connects inputs to outputs in a table, graph, equation, or context.

An input is the value supplied to a relationship, and an output is the value produced or paired with that input. The words input and output describe roles. In one situation the input might be hours and the output cost; in another the input might be a temperature and the output a predicted energy use.

A rule explains how the output depends on the input. A table can reveal the rule through repeated changes, an equation can state it symbolically, a graph can show the pairs that obey it, and a context can tell what the calculation means. A useful rule must reproduce the known pairs, not merely fit the first row.

Variables such as $x$ and $y$ are common labels, but the meaning comes from the situation. Before writing a rule, decide which quantity is being chosen or supplied and which quantity is determined from it. Clear variable meaning prevents the common error of reversing the relationship.

Stop and Discuss
  1. What is the difference between an input and an output?
  2. Why is “input means x” not a complete definition?
  3. How can a table provide evidence for a rule?
MATH NOTES
Input → Rule → Output

Input: the value you start with.

Rule: the operation or relationship that connects the quantities.

Output: the resulting value.

Example: $x \to 2x+3 \to y$. If $x=4$, then $y=11$.

I can apply an input-output rule to generate missing values and ordered pairs.

Applying a rule forward means substituting an input and carrying out the stated operations. If $f(x)=2x-5$, then $f(6)$ means use $6$ as the input: $2(6)-5=7$. Function notation packages the input into the name of the rule; it does not mean $f$ multiplied by $x$.

Sometimes the output is known and the input is missing. Then the same rule can be reasoned backward. If $y=4x+1$ and the output is $29$, you are looking for the input that makes $4x+1=29$. This turns an input-output rule into an equation to solve.

An ordered pair keeps the direction visible. The input is written first and the output second: $(\text{input},\text{output})$. A calculated output becomes useful evidence only when it stays connected to the input that produced it.

Stop and Discuss

  2. How does a known output turn a function rule into an equation?
  3. Why is the order of values in an ordered pair important?
MATH NOTES
Forward and Backward Reasoning

Forward: input known → substitute → compute output.

Backward: output known → set rule equal to output → solve for input.

For $y=5x-2$, input $3$ gives output $13$; output $13$ can also be used to recover input $3$.

I can assess whether a rule gives one output for each input in a situation.

A function assigns exactly one output to each input. Different inputs are allowed to share the same output. The problem occurs only when the same input is paired with two different outputs, because the rule would be giving two conflicting results for one starting value.

In a table, scan the input column for repeats. A repeated input is not automatically a problem; check whether its output also repeats. In a mapping diagram, each input should have exactly one arrow leaving it. In a graph, the same idea appears as the vertical-line test: one input location should not hit the graph at two different output heights.

The function test is about consistency, not about whether the relationship is linear or simple. A complicated curve can be a function, and a small list of points can fail to be one. Keep the definition centered on what each individual input is allowed to do.

Stop and Discuss
  1. What makes a relationship a function?
  2. Can two different inputs have the same output in a function? Explain.
  3. A table repeats input 2 twice with output 7 both times. Does that repetition alone violate the function rule?
MATH NOTES
Function Check

Allowed: many inputs may point to the same output.

Not allowed: one input points to two different outputs.

Table check: look for a repeated input with conflicting outputs. Mapping check: each input has one arrow. Graph check: a vertical line should not hit the graph more than once.
